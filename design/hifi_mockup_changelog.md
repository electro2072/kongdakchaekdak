### **v1.8 변경 이력 (2026-08-27)** — 사용자가 "사용자가 태블릿(아이패드) 환경이면 디자인 대응이 필요 없냐"고 질문, 이어서 "갤럭시 폴드 같은 폴더블 기기도 나오는 세상"이라는 지적을 추가. 검토 결과 지금까지 모든 화면이 **폰 폭(iPhone 375~430px) 기준으로만** 제작되어 있었고, 기획서에도 태블릿 지원 범위가 명시된 적이 없었음을 확인했습니다. React Native 앱은 별도 설정 없이는 iPad에서도 그대로 실행되고, 갤럭시 폴드처럼 펼쳤을 때 태블릿급 폭이 되는 기기도 있어 "아이패드냐 아니냐"가 아니라 **화면 폭 구간(breakpoint)** 기준으로 대응하는 게 맞다고 판단 — iOS 사이즈 클래스·Android Material 3 window size class가 실제로 이 방식(compact/expanded)을 쓰고 있어 아이패드와 폴드 펼침 상태를 같은 로직으로 커버할 수 있습니다. 사용자가 "태블릿 디자인 진행"을 선택했고, 리스트/그리드형 화면 재설계는 "핵심 3개 화면만"(전체 11개 프레임 검토가 아니라) 범위로 확정.

**대응 방식** — 폭 600px 미만은 지금까지의 폰 레이아웃(Compact) 그대로. 600px 이상(Expanded)에서: ① 온보딩·로그인·회원가입·공유범위 선택 같은 폼/단일 컬럼 화면은 **본 문서에서 별도로 새로 그리지 않음** — 실제 구현 시 콘텐츠 폭에 max-width(약 480px)를 걸고 화면 중앙에 배치하는 규칙 하나로 처리 가능하기 때문(프론트 구현 시점에 CSS/스타일 규칙으로 적용). ② 콘텐츠가 많은 리스트/그리드형 화면 3개는 실제로 새 레이아웃을 그려 아래에 추가: **Frame 03 서재 목록**, **Frame 05.1 대시보드**, **Frame 02 일정 탭**(각 라이트/다크). **(v1.9에서 이 세 화면 모두 다시 그려졌습니다 — 최초 초안은 폰 요소를 여백만 넓혀 배치한 수준이었다는 피드백을 받아 재작업, 아래 v1.9 변경 이력 참고.)**

**새 프레임 요소** — 태블릿용 `.tablet-frame`(640×900, 코너 반경 22px) + `.tablet-statusbar`를 신설했습니다. 아이패드는 Dynamic Island가 없는 기기라 폰 프레임과 달리 상태바에 island를 넣지 않았고, 그 외 시간·신호·Wi-Fi·배터리 아이콘은 폰 프레임과 동일하게 재사용해 시각적 일관성을 유지했습니다. 하단 탭바는 이번 범위에서 폰과 동일한 형태(아이콘·글자만 살짝 확대)로 유지 — 사이드바/레일 형태로 바꿀지는 내비게이션 전체 구조에 관한 별도 결정이 필요해 이번 라운드에는 포함하지 않았습니다(아래 "다음 단계" 참고).

### **v1.9 변경 이력 (2026-08-27) — v1.8 확장 레이아웃 재작업** — 사용자가 v1.8의 확장(Expanded) 레이아웃 3종을 보고 "다 못생겼다, 넓어지는 게 무슨 의미인지 먼저 알아야 할 것 같다"고 직접적으로 지적. 스크린샷을 다시 보니 맞는 지적이었습니다 — 폰용 카드·차트를 그대로 두고 여백만 넓혀서 배치한 정도였고, 특히 대시보드는 콘텐츠가 프레임 상단 40%에만 몰려 있고 나머지는 빈 공간이었습니다. **문제의 본질: 화면이 넓어지는 것 자체가 목적이 아니라, 그 폭으로 "더 많이 보여주거나" "더 크게 보여줘야" 의미가 있는데, 그냥 같은 크기의 요소를 여백만 넓혀 흩어놓았을 뿐이었음.** 세 화면을 다시 설계:

  - **서재 목록** — 가로 리스트 행(작은 표지+텍스트) 2열 그리드를 폐기하고, **표지 중심 3열 서가 그리드**(책 4권 → 6권)로 교체. 표지 이미지를 크게(세로 비율 3:4.2) 키워서 실제 책장을 보는 느낌으로, 더 많은 책을 한눈에 보여주는 것 자체가 넓은 화면의 이점이 되도록 함.

  - **대시보드** — 통계 카드를 2개(완독 수·읽은 페이지)에서 **4개 전체 폭 배치**(연속 독서일·평균 완독기간 추가)로 확장, 장르 비율 도넛차트(76px→140px)와 월별 추이 막대그래프(높이 70px→130px, 월 라벨 추가)를 실제로 훨씬 크게 키움, 하단에 **"최근 활동"** 리스트(완독 처리·사진 추가·소감 작성 3건)를 신규로 채워 넣어 프레임 하단까지 실제 콘텐츠로 채워지도록 함.

  - **일정 탭** — 왼쪽에 **"다가오는 일정"** 미니 리스트(모임·완독 목표일 2건), 오른쪽엔 기존 텍스트 행이었던 "읽고 있는 책" 카드를 표지+진행률 바가 있는 큰 카드로 키우고 **"최근 완독한 책"** 4칸 그리드(전체보기 포함)를 신규 추가 — 양쪽 모두 프레임 하단까지 실제 콘텐츠로 채움.

세 화면 모두 라이트·다크 각각 재검증. `<div>`/`</div>` 태그 균형(1666=1666) 및 Playwright 스크린샷으로 빈 공간이 크게 줄고 표지 그리드·확대된 차트·신규 리스트가 의도대로 렌더링되는지 확인.

### **v1.17 변경 이력 (2026-09-08)** — "지금까지 쓴 문구들이 딱딱하다"는 피드백을 받아, 사용자가 별도로 준비한 UX 보이스 확장 문서("밥상" 레이어 — 책거리/콩송편 은유를 §1 세 가지 규칙(빈도가 높을수록 담백하게 · 잘 됐을 때만 맛을 낸다 · 읽은 양을 음식으로 평가하지 않는다) 안에서만 쓰는 방식)를 기준으로, 이 문서 안에 실제로 존재하는 문구 중 규칙상 "맛을 내도 되는" 자리만 골라 교체했습니다. 실패·경고·삭제·확인 같은 자리와 고빈도 자리(저장/등록 토스트, 사진 추가, 소감 작성)는 원칙대로 손대지 않았습니다:

  - Frame 03.1 책 상세 — 완독 버튼 `다 읽었어요 (완독 처리)` → `다 읽었어요` (버튼 라벨은 은유 없이 직역·간결화 원칙)

  - Frame 05.1 대시보드 (Compact·Expanded 공통) 리캡 하이라이트 카드 — `이번 분기 가장 많이 읽은 장르는 소설 / 가장 오래 곱씹은 책은 『아몬드』(9일)` → `이번 분기 입맛은 소설이었어요 / 『아몬드』를 9일 동안 뜸 들여 읽으셨어요`(Expanded는 `12일 연속 독서 기록 중이에요` → `12일째 야금야금 이어가는 중이에요` 추가) — 리캡은 "맛 가장 진하게" 내도 되는 표면

  - Frame 05.1 Expanded "최근 활동" 리스트 — `『아몬드』 완독 처리 완료` → `『아몬드』 책거리 완료`(사진 추가·소감 작성 두 항목은 고빈도라 변경 없음)

  - Frame 07 서재 탭 최초 빈 상태 — 제목 `아직 등록한 책이 없어요` → `아직 상이 비어 있어요`, 설명 `읽고 있는 책을 등록하고 독서 기록을 시작해보세요` → `한 권만 올려도 서재가 시작돼요`

  - Frame 10 알림 목록 — `7월 독서 리캡이 준비됐어요` → `7월 밥상이 차려졌어요`(같은 목록의 그룹 참여·공유 반응 알림 2건은 "잘 됐을 때"이지만 이미 담백한 사실 전달형이라 원문 유지 대상으로 판단해 손대지 않음)

로그인 태그라인(`오늘 읽은 한 페이지를 자랑해보세요`)은 스토어 스크린샷 캡션으로 이미 확정된 문구라 이번에도 그대로 유지했습니다. 이 문서에 실제 마크업이 없어 손대지 못한 나머지 항목(가입 완료 다이얼로그, 복귀 배너, 마일스톤 문구 등)은 프론트 요청 문서에 별도로 정리했습니다. 라이트·다크 각각 Playwright로 재검증, `<div>` 태그 균형 변경 없음(문구 교체만, 신규 요소 없음).
