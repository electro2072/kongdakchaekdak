React Native 앱은 별도 설정 없이는 iPad에서도 그대로 실행되고, 갤럭시 폴드처럼 펼쳤을 때 태블릿급 폭이 되는 기기도 있어 "아이패드냐 아니냐"가 아니라 화면 폭 구간(breakpoint) 기준으로 대응하는 게 맞다고 판단 — iOS 사이즈 클래스·Android Material 3 window size class가 실제로 이 방식(compact/expanded)을 쓰고 있어 아이패드와 폴드 펼침 상태를 같은 로직으로 커버할 수 있습니다. 사용자가 "태블릿 디자인 진행"을 선택했고, 리스트/그리드형 화면 재설계는 "핵심 3개 화면만"(전체 11개 프레임 검토가 아니라) 범위로 확정.
대응 방식 — 폭 600px 미만은 지금까지의 폰 레이아웃(Compact) 그대로. 600px 이상(Expanded)에서: ① 온보딩·로그인·회원가입·공유범위 선택 같은 폼/단일 컬럼 화면은 본 문서에서 별도로 새로 그리지 않음 — 실제 구현 시 콘텐츠 폭에 max-width(약 480px)를 걸고 화면 중앙에 배치하는 규칙 하나로 처리 가능하기 때문(프론트 구현 시점에 CSS/스타일 규칙으로 적용). ② 콘텐츠가 많은 리스트/그리드형 화면 3개는 실제로 새 레이아웃을 그려 아래에 추가: Frame 03 서재 목록, Frame 05.1 대시보드, Frame 02 일정 탭(각 라이트/다크). (v1.9에서 이 세 화면 모두 다시 그려졌습니다 — 최초 초안은 폰 요소를 여백만 넓혀 배치한 수준이었다는 피드백을 받아 재작업, 아래 v1.9 변경 이력 참고.)
새 프레임 요소 — 태블릿용 .tablet-frame(640×900, 코너 반경 22px) + .tablet-statusbar를 신설했습니다. 아이패드는 Dynamic Island가 없는 기기라 폰 프레임과 달리 상태바에 island를 넣지 않았고, 그 외 시간·신호·Wi-Fi·배터리 아이콘은 폰 프레임과 동일하게 재사용해 시각적 일관성을 유지했습니다. 하단 탭바는 이번 범위에서 폰과 동일한 형태(아이콘·글자만 살짝 확대)로 유지 — 사이드바/레일 형태로 바꿀지는 내비게이션 전체 구조에 관한 별도 결정이 필요해 이번 라운드에는 포함하지 않았습니다(아래 "다음 단계" 참고).
v1.9 변경 이력 (2026-08-27) — v1.8 확장 레이아웃 재작업 — 사용자가 v1.8의 확장(Expanded) 레이아웃 3종을 보고 "다 못생겼다, 넓어지는 게 무슨 의미인지 먼저 알아야 할 것 같다"고 직접적으로 지적. 스크린샷을 다시 보니 맞는 지적이었습니다 — 폰용 카드·차트를 그대로 두고 여백만 넓혀서 배치한 정도였고, 특히 대시보드는 콘텐츠가 프레임 상단 40%에만 몰려 있고 나머지는 빈 공간이었습니다. 문제의 본질: 화면이 넓어지는 것 자체가 목적이 아니라, 그 폭으로 "더 많이 보여주거나" "더 크게 보여줘야" 의미가 있는데, 그냥 같은 크기의 요소를 여백만 넓혀 흩어놓았을 뿐이었음. 세 화면을 다시 설계:
· 서재 목록 — 가로 리스트 행(작은 표지+텍스트) 2열 그리드를 폐기하고, 표지 중심 3열 서가 그리드(책 4권 → 6권)로 교체. 표지 이미지를 크게(세로 비율 3:4.2) 키워서 실제 책장을 보는 느낌으로, 더 많은 책을 한눈에 보여주는 것 자체가 넓은 화면의 이점이 되도록 함.
· 대시보드 — 통계 카드를 2개(완독 수·읽은 페이지)에서 4개 전체 폭 배치(연속 독서일·평균 완독기간 추가)로 확장, 장르 비율 도넛차트(76px→140px)와 월별 추이 막대그래프(높이 70px→130px, 월 라벨 추가)를 실제로 훨씬 크게 키움, 하단에 "최근 활동" 리스트(완독 처리·사진 추가·소감 작성 3건)를 신규로 채워 넣어 프레임 하단까지 실제 콘텐츠로 채워지도록 함.
· 일정 탭 — 왼쪽에 "다가오는 일정" 미니 리스트(모임·완독 목표일 2건), 오른쪽엔 기존 텍스트 행이었던 "읽고 있는 책" 카드를 표지+진행률 바가 있는 큰 카드로 키우고 "최근 완독한 책" 4칸 그리드(전체보기 포함)를 신규 추가 — 양쪽 모두 프레임 하단까지 실제 콘텐츠로 채움.
세 화면 모두 라이트·다크 각각 재검증. <div>/</div> 태그 균형(1666=1666) 및 Playwright 스크린샷으로 빈 공간이 크게 줄고 표지 그리드·확대된 차트·신규 리스트가 의도대로 렌더링되는지 확인.

· Frame 02 태블릿 레이아웃 재구성 — 사용자가 "태블릿에서는 일정(캘린더)이 맨 위에 길게 있는 게 맞다, 그 아래 좌측엔 '읽을 차례예요'+'일정이 있어요' 카드, 우측엔 '다가오는 일정', 그 아래 새 책 등록하기가 전체 폭으로 깔려야 한다"고 요청. v1.9에서는 좌(캘린더+오늘 카드+다가오는 일정)/우(새책 등록+읽고 있는 책+최근 완독) 2단 구성이었는데, 요청대로 재배치: ① 캘린더를 화면 최상단에 전체 폭으로 배치, ② 그 아래 좌="읽을 차례예요" 카드 + "이번주 일정이 있어요" 카드, 우="다가오는 일정" 리스트로 나란히 배치, ③ "새 책 등록하기" 버튼을 전체 폭으로 그 아래 배치, ④ "읽고 있는 책"은 위 가로 스크롤 패턴 적용(2권→3권, 아몬드·채식주의자·불편한 편의점), ⑤ "최근 완독한 책" 4칸 그리드는 그대로 최하단 유지. 프레임 안에 다 들어가도록 여백·폰트 크기를 촘촘히 조정해 재검증(스크롤 영역 실측 오버플로 133px → 9px로 축소, 사실상 프레임 안에 수렴).
두 변경 모두 라이트·다크 각각 재검증, <div>/</div> 태그 균형(1686=1686) 및 Playwright 스크린샷으로 확인.
v1.11 변경 이력 (2026-08-28) — 사용자가 "6개 장르에 고정 색을 부여하는 걸 염두에 두고 있다"고 언급, 적용 위치로 ① 장르 비율 도넛차트, ② 관심분야·장르 선택 칩, ③ 서재 목록 책 태그 3곳을 지정. 기존에는 소설·에세이·자기계발·인문 4개 장르만 --chart1~4로 고정색이 있었고 과학·경제·경영은 색이 없어(도넛차트는 등수 기반으로 상위 3개 장르만 색을 주고 나머지는 회색 "기타"로 뭉뚱그리는 방식) 완전한 고정 매핑이 아니었습니다. dataviz 스킬의 공식 팔레트 검증 스크립트(라이트니스 밴드·채도 하한·색약 시뮬레이션 CVD 분리도·명도대비)로 기존 4색과 어울리면서 색약 안전성 기준(정상시야 ΔE≥15, 색약 ΔE≥8/하한 6)을 통과하는 신규 2색을 탐색 — 과학은 "청화백자" 모티프의 청화블루(#0089ff/다크 #009af3, --chart5), 경제·경영은 처음 시도한 "고서 갈색"이 딥테라노피아 시뮬레이션에서 기존 그린과 색약 분리도 미달(ΔE 3.7, 기준 6 미달)로 탈락해 "먹빛 남색"(먹이 전통적으로 띠는 푸른 광택 "청묵"에서 착안)으로 전환한 먹빛 남색(#1c1a46/다크 #98bed3, --chart6)으로 확정 — 사용자 확인("색깔 괜찮아 보이네요") 후 3곳에 적용:
· 도넛차트 — 상위 3개만 색을 주고 나머지를 회색 "기타"로 묶던 로직 대신, 4번째 conic-gradient 구간을 --n200(회색)에서 --chart4(인문/보라)로 교체. 6개 장르가 이제 모두 고정색을 가지므로 "기타" 버킷 자체가 더 이상 필요 없다는 판단(구조 변경 필요 사항은 프론트 요청 문서로 별도 전달).
· 관심분야·장르 선택 칩 — Frame 01.1/01.2/05.2에 남아있던 구버전(v1.2 시절 코랄→자기계발·시안→과학 매핑) 하드코딩 잔재를 새 매핑으로 정정(자기계발: 분홍→치자, 과학: 치자→신규 청화블루)하고, 인문·경제·경영 칩도 신규 색 적용. 칩은 채도 있는 배경 + 대비되는 텍스트 색(라이트/다크 각각 명도대비 계산 후 더 잘 보이는 쪽 선택 — 예: 다크모드 인문은 흰 글씨가 검정보다 대비가 더 높아 예외적으로 흰 글씨 사용) 규칙을 그대로 따랐습니다.
· 서재 목록 책 태그 — Frame 03(서재 목록) 폰·태블릿 카드에 장르 배지를 신규 추가(폰 2권·태블릿 6권, 예시용 장르 배정: 아몬드→소설, 채식주의자→에세이, 불편한 편의점→자기계발, 달러구트 꿈 백화점→인문, 구의 증명→과학, 저주토끼→경제·경영). 배지는 칩과 다른 톤 규칙(옅은 틴트 배경 + 진한 텍스트, 다크모드는 반전) 사용 — 기존 배지 표(예: 인문 #602f72)를 그대로 재사용하지 않고 채도 있는 칩 배경 대비용으로 새로 도출한 값과 구분해서 각 용도에 맞는 색만 사용했습니다.
