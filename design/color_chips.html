📗 독서 자랑 어플 — 컬러 팔레트 v1.2

메인 테마: 연두색(Yellow-Green) · OKLCH 기반 설계 · WCAG 대비 검증 완료 · 2026-07-21 (v1.1: 카테고리 포인트 멀티컬러 추가 · v1.2: primary 그린을 더 생동감 있는 톤으로 재조정)

1. Primary — 연두 (Brand)

OKLCH hue 140°(기존 128°에서 조정, sRGB 안에서 이 명도대에 최대 채도가 나오는 지점), 명도(L)만 단계별로 낮춰 밝은 배경용(50~200)부터 진한 텍스트/버튼용(700~900)까지 구성했습니다.

💡 v1.2 변경 이유 — 기존 hue 128°는 명도를 낮춰 흰 텍스트 대비(4.5:1)를 맞추다 보니 올리브·카키에 가까운 칙칙한 톤이 됐습니다. 같은 명도에서 채도가 최대로 나오는 hue를 다시 탐색해 140°로 옮기고 채도를 전 단계에서 끌어올렸습니다 — 대비 요건(버튼 700 + 흰 텍스트 4.5:1 이상)은 그대로 유지하면서 훨씬 생기 있는 그린이 됐습니다.

2. Neutral — 그레이 (텍스트/배경/구분선)

완전 무채색이 아니라 연두와 같은 계열(hue 120°)의 아주 옅은 채도를 살짝 섞어, 화면 전체 톤이 붕 뜨지 않고 은은하게 어우러지도록 했습니다.

3. Status — 상태색 (고정, 테마 영향 안 받음)

성공(success)은 브랜드 컬러(primary-600)를 그대로 재사용합니다 — "완독/성공"이 곧 우리 브랜드 그린이라는 의미로 자연스럽게 연결됩니다. 경고·오류·정보는 브랜드 그린과 혼동되지 않도록 별도 색상을 썼습니다. 단, 상태색은 색상만으로 의미를 전달하지 않고 반드시 아이콘 + 텍스트 라벨을 함께 표기합니다 (색맹 시뮬레이션상 경고/오류 계열 색상 간 구분이 완벽하지 않기 때문 — 아래 4번 검증 참고).

4. 접근성(대비) 검증 결과

텍스트 대비는 WCAG AA 기준(본문 4.5:1 / 큰 글자·아이콘 3:1)으로, 색맹 안전성은 dataviz 스킬의 OKLab ΔE 시뮬레이션(Machado-Oliveira-Fernandes 2009)으로 검증했습니다. 아래는 실제 validate_palette.js 실행 결과입니다.

7. 다크모드 — 연두를 그대로 Primary로 사용

라이트모드와 같은 hue(140°, v1.2에서 조정)를 유지하되, 명도(L)만 dark 모드 밴드(OKLCH L 0.48~0.67)에 맞춰 전체적으로 더 밝고 채도 있게 조정했습니다. 즉 "다른 색"이 아니라 같은 연두의 다크모드 버전입니다 — 브랜드 정체성은 그대로 유지됩니다.

Primary 다크 스케일 (hue 140° 동일)

상태색 (다크 배경 전용, 라이트모드 색과 다름)

라이트모드 상태색(흰 배경 기준으로 튜닝)을 다크 배경에 그대로 쓰면 대비가 무너집니다(예: error #b6143f는 다크 배경 대비 2.64:1로 FAIL). 그래서 다크 전용으로 더 밝게 다시 튜닝했습니다.

8. 카테고리 포인트 멀티컬러 (v1.1 추가, 파스텔톤)

지금까지는 연두 하나만 포인트로 써왔는데, 장르 태그·도넛차트처럼 "여러 항목을 구분"해야 하는 곳엔 색이 하나뿐이면 다 비슷해 보입니다(예: 대시보드 장르 도넛이 전부 초록 계열 명암차만 다른 상태). dataviz 스킬의 categorical 컬러 공식(고정 순서 + 색맹 시뮬레이션 all-pairs 검증)으로 연두를 포함해 4개 포인트 컬러를 새로 확정했습니다. 채도를 낮추고 명도를 높여 파스텔톤으로 다시 뽑았고, 색상환에서 서로 최대한 떨어진 지점(초록 140° · 코랄 15° · 하늘색 210° · 라벤더 285°)을 자동 탐색해서 고른 조합이라 색맹 시뮬레이션(protan/deutan/tritan) 기준으로도 전부 구별됩니다. (v1.2에서 primary 그린의 hue가 128°→140°로 바뀌면서 이 조합도 새 그린 기준으로 재검증했습니다.)
