## 스크립트 실행에 대한 주의

`gen_*`/`check_*` 스크립트는 다음 두 외부 경로에 의존합니다 (이 저장소 밖에 있음):

- `culori` npm 패키지 — 로컬에서 재현하려면 `npm install culori` 필요
- dataviz 스킬의 `validate_palette.js` (Anthropic 번들 스킬 경로) — 이 검증기가 없으면 색맹 안전성/대비 체크 로직을 다시 구현해야 함

즉 이 스크립트들은 **"이 색이 어떻게 도출됐는지"를 기록해두기 위한 자료**이고, 그대로 재실행 가능한 빌드 스크립트는 아닙니다.

## 버전 관리 방식

- 각 산출물은 파일명에 `v1`, `v2` 형태로 버전을 표기합니다.
- 이 폴더가 git으로 커밋되기 시작한 시점(2026-07-21)부터는, 새 버전을 만들 때 기존 파일을 덮어쓰지 않고 새 파일(`_v2.html` 등)을 추가하거나, 같은 파일 안에 변경 이력(changelog) 섹션을 남기는 두 방식을 상황에 따라 씁니다 — 와이어프레임 문서가 후자 방식(문서 내 changelog)의 예시입니다.
- git 커밋 이력 자체가 세부 변경 diff를 보존하므로, 파일명 버전 표기는 "현재 어떤 버전을 보고 있는지"를 사람이 알아보기 위한 용도이고, 실제 변경 이력 추적은 git log가 담당합니다.
- **(2026-07-22부터 표준화)** HTML 산출물 3종(`color_chips.html`, `typography_and_icons.html`, `hifi_mockup_v1.html`) 모두 `<h1>` 제목과 상단 메타 정보 바로 아래에 `.doc-note` 스타일의 버전 changelog 박스를 둡니다 — 버전 번호별로 날짜와 변경 내용을 한 줄씩 누적 기록. git log를 뒤지지 않고도 파일을 열어보는 것만으로 "지금 이게 몇 버전이고 뭐가 바뀌었는지"를 바로 알 수 있게 하기 위함입니다. 이 위와 아래 표의 "현재 버전" 열은 그 `.doc-note`의 최신 항목과 항상 일치해야 합니다(둘 중 하나만 갱신하고 잊어버리지 않도록 주의).
- 이 저장소(로컬 클론)와 claude.ai 프로젝트 문서함의 "확정" 버전 표기가 git 동기화 문제로 어긋날 수 있다는 것이 2026-07-22에 확인되었습니다 — 아래 "로컬 저장소와 claude.ai 프로젝트 문서 간 버전 불일치 주의" 참고. 실제 파일 상태(`.doc-note`)를 항상 1차 소스로 삼으세요.
