# 소셜 로그인 온보딩 — 실기기(에뮬레이터) 시나리오

> 출처: 프론트엔드 에이전트 요청서(2026-08-29, `C:\Users\User\Downloads\온보딩 테스트.md`).
> `scenarios/social-login.md`(백엔드 API 블랙박스)와 **별개** — 실제 RN 앱 UI를 눌러서 확인하는
> 프론트엔드 온보딩 시나리오. 개발현황.md 41·43·44번 항목 관련.

## 성격 — 사람이 직접 실행

**실제 카카오/구글/네이버 계정 로그인(ID/PW 입력, 동의 화면)은 사람이 수행해야 한다.**
테스터 에이전트는 에뮬레이터를 구동/조작할 수 없고 소셜 계정 로그인을 자동화할 수단이 없다.
따라서 이 시나리오는 **사용자가 Android 에뮬레이터에서 직접 눌러 확인**하고, 테스터는
(1) 사전 점검(빌드/타입/계약이 온전한지) + (2) 백엔드 측 A→B 계약 검증 + (3) 실행 체크리스트 제공.

## 0. 준비

| 항목 | 내용 |
|---|---|
| 대상 플랫폼 | **Android만** (iOS는 Mac/`pod install` 불가로 이번 범위 제외) |
| 앱 빌드 | `frontend`에서 `npm install` 완료, 에뮬레이터에 최신 빌드 설치 |
| 백엔드 | 로컬 기동. BUG-03 조각1(`6b710b1`) 이후 `.env` AWS 키 없이도 `gradle bootRun --args="--spring.profiles.active=local"` 정상 기동 |
| `API_BASE_URL` | 프론트 `.env`가 에뮬레이터 기본값 `http://10.0.2.2:8080`인지 확인. 실기기면 PC LAN IP로 |
| 소셜 앱 등록 | 카카오/구글/네이버 3사 등록 + 네이티브 키 반영 완료(40번 항목) |
| 테스트 계정 | 3사 각 1개 이상 실제 로그인 가능한 계정 |
| **실행 순서** | 백엔드 H2 인메모리 → **A(신규) 먼저, 서버 재기동 없이 같은 계정으로 B(재로그인) 이어서**. C(취소)는 아무 때나 독립 실행 |

## C. 로그인 취소

"OOO로 시작하기" 탭 후 로그인/동의 화면에서 뒤로가기/취소.

| # | 시나리오 | 기대 결과 |
|---|---|---|
| FE-SL-07 | 카카오 로그인 취소 | 로그인 화면 복귀. **⚠️ "로그인 실패" 얼럿이 뜨는 게 정상** (아래 참고) |
| FE-SL-08 | 네이버 로그인 취소 | 로그인 화면으로 조용히 복귀, **얼럿 없음** |
| FE-SL-09 | 구글 로그인 취소 | 로그인 화면으로 조용히 복귀, **얼럿 없음** |

**FE-SL-07 참고 (버그 아님)**: `@react-native-seoul/kakao-login` v6.0.4는 "사용자 취소" 전용 에러
코드가 없어 취소도 일반 실패와 동일 처리(`services/socialAuth/kakaoAuth.ts` 주석). **카카오만
취소 시 "로그인 실패" 얼럿 → 알려진 제약, 정상 동작**. 리포트에 버그로 등록 금지. 다만 실제 취소
시 에러 메시지/코드 패턴을 확인해 알려주면 프론트가 그 패턴으로 취소 구분 개선을 검토.

공통(3건): 취소 후 버튼이 다시 눌리는 상태로 복귀(스피너 안 멈춤), 다른 두 버튼도 정상 작동.
