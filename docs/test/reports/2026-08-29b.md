## 이 시나리오의 성격

**FE-SL-01~09는 사람이 Android 에뮬레이터에서 직접 눌러 확인해야 한다** — 테스터 에이전트는
에뮬레이터를 조작할 수 없고 카카오/구글/네이버 계정 로그인(ID/PW + 동의 화면)을 자동화할 수 없다.
테스터가 대신 한 것:
1. **사전 점검** — 사람이 실행하기 전에 빌드/타입/계약/취소 처리가 온전한지 (§1)
2. **백엔드 A→B 계약 검증** — `isNewUser` true→false 전환을 API 레벨에서 (§2, 유효 카카오 토큰 필요)
3. **실행 체크리스트** — §3, 사람이 실제/판정만 채우면 됨

### 취소 처리 — 코드상 시나리오 문서와 정확히 일치

| provider | 취소 시 동작 (코드) | 시나리오 기대 |
|---|---|---|
| 카카오 (`kakaoAuth.ts`) | 취소 전용 코드 없음 → 일반 에러로 throw → `LoginScreen` catch → **Alert** | FE-SL-07: "로그인 실패" 얼럿 = 정상(알려진 제약) ✅ 일치 |
| 네이버 (`naverAuth.ts`) | `result.failureResponse?.isCancel` → `null` 반환 → `LoginScreen`에서 `=== null` → **조용히 return** | FE-SL-08: 얼럿 없음 ✅ 일치 |
| 구글 (`googleAuth.ts`) | `isSuccessResponse` false → `GOOGLE_SIGN_IN_CANCELLED` 심볼 반환 → `LoginScreen`에서 `=== 심볼` → **조용히 return** | FE-SL-09: 얼럿 없음 ✅ 일치 |

3개 경로 모두 `finally { setLoadingProvider(null) }` — 취소/실패 후 로딩 스피너가 풀리고 버튼이
다시 눌리는 상태로 복귀함(코드상 보장). 실제 UX는 사람이 확인.

### `isNewUser` 분기 (LoginScreen) — 코드 리뷰 ✅

`completeSocialLogin(accessToken, isNewUser)`:
```
setAccessToken(accessToken);          // 두 경우 다 토큰 먼저 저장
if (isNewUser) navigation.navigate('Signup');   // 신규 → 회원가입 화면
else login();                                    // 기존 → 바로 탭 진입
```
백엔드 `TokenResponse.isNewUser`(record boolean, `"isNewUser"`로 직렬화 — 2026-08-29 리포트 §1-3
확인) 와 필드명 일치. 프론트 `authApi.ts` `interface TokenResponse { isNewUser: boolean }` 도 일치.

## 2. 백엔드 A→B 계약 검증 (`isNewUser` true → false)

> **유효한 카카오 access token 1개 필요** — 사용자 제공 대기 중.
> 확보되면 로컬 백엔드(H2, 재기동 없이)에서:
>
> | 단계 | 확인 |
> |---|---|
> | ① `POST /api/auth/kakao` {유효 토큰} | 200, **`isNewUser: true`**, JWT 발급, `users`에 `social_provider='kakao'` 행 1개 생성 |
> | ② ①의 JWT로 `GET /api/auth/me` | 200, 신규 유저 정보 (닉네임 = 카카오 닉네임 또는 랜덤 폴백) |
> | ③ **같은 카카오 토큰**으로 `POST /api/auth/kakao` 재요청 | 200, **`isNewUser: false`**, 동일 `sub`, `users` 행 증가 없음 |
>
> 이게 통과하면 FE-SL-01(신규→회원가입 화면)과 FE-SL-04(재로그인→바로 메인)의 **백엔드 계약이
> 보장**되고, 사람은 프론트 화면 전환만 확인하면 됨.
>
> *(구글/네이버는 테스터가 해당 계정 토큰을 만들 수 없어 A→B API 검증은 카카오로만. 화이트박스
> `SocialAuthControllerTest`가 3사 모두 `isNewUser` true/false를 커버함 — 2026-08-29 리포트 §1-3.)*

## 4. 알려진 제약 / 참고
- iOS는 이번 범위 제외 (Mac/`pod install` 불가).
- 온보딩 화면(SignupScreen)의 성별/관심분야 입력은 **아직 백엔드로 저장 안 됨** (`PATCH /api/users`
  호출 없음, 로컬 state만). "시작하기" = 로컬 `login()`. 온보딩 데이터 영속화는 별도 작업 대상 —
  이 시나리오 범위 밖이지만 기록해둠.
- FE-SL-07 카카오 취소 시 얼럿 = 라이브러리 제약, 버그 아님.
