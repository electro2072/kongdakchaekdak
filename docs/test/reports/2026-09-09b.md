## 🐛 BUG-20260909-21 — gender 값이 FE↔BE 불일치로 항상 유실

- 심각도: **major**
- 영역: frontend ↔ backend 계약 불일치 (수정은 FE 또는 BE)
- 상태: open
- 재현: 로그인 → 프로필 편집 → 저장. 또는 그냥 앱 부팅.
- 실제:
  - 매 부팅/저장 후 logcat: `[WARN][userApi] 알 수 없는 gender 값 — 우선 null로 처리: NONE`
  - `PATCH /api/users/{id}` 응답의 `gender: "NONE"` 을 FE `mapGenderResponseToKey`가 인식 못 함.
- 원인:
  - 백엔드 `com.kongdakchaekdak.domain.user.Gender` enum = **`MALE` / `FEMALE` / `NONE`** (대문자 enum 이름 직렬화)
  - 프론트 `src/constants/profileOptions.ts` `GENDER_OPTIONS[].key` = **`'female'` / `'male'` / `'unspecified'`** (소문자)
  - `userApi.ts` `KNOWN_GENDER_KEYS = ['female','male','unspecified']` — 백엔드 값과 **한 개도 안 겹침** → 항상 `null`.
  - 역방향도 깨짐: FE가 PATCH 바디에 `gender: 'male'` 을 보내면 Jackson이 `Gender` enum(`MALE`)으로 역직렬화 못 함(대소문자·값 불일치) → 400 또는 무시.
- 기대: 사용자가 프로필에서 성별을 고르면 저장되고, 다시 열었을 때 그 값이 선택돼 있어야 함.
- 영향: 프로필 4개 편집 필드(닉네임/한줄소개/성별/관심분야) 중 **성별이 왕복 불가**. 닉네임/한줄소개는 정상(S2 §5로 닉네임 확인). interests는 이번 세션 미확인.
- 의심 지점: `frontend/src/services/userApi.ts` `KNOWN_GENDER_KEYS` / `mapGenderResponseToKey`, `frontend/src/constants/profileOptions.ts` `GENDER_OPTIONS`, `backend/.../user/Gender.java`. FE 주석(`userApi.ts`)에 "gender 값 형식 재확인 필요"가 이미 적혀 있음 — 그 재확인이 이번에 실측으로 필요함이 드러남.
- 넘길 대상: reading-record-frontend-agent (+ 백엔드와 값 형식 합의 필요)

## OBS-20260909-22 — 닉네임 규칙이 FE/BE 불일치 (정보)

- 백엔드 `UserUpdateRequest.nickname` = `@Size(max=30)` **뿐** (패턴·최소길이 없음).
- 프론트 편집 화면 = **2~10자 + `/^[가-힣a-zA-Z0-9]*$/`** (특수문자·공백·이모지 금지).
