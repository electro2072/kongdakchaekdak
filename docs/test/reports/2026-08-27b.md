### BUG-20260827-02  프론트 typecheck 깨짐 — 신규 테스트 파일의 jest.mock 스프레드
- 심각도: **major** (CI에서 `npm run typecheck` 게이트가 있으면 빌드 차단, IDE 전체 빨간줄)
- 영역: frontend · 상태: **open**
- 재현: `frontend/`에서 `npm run typecheck`
- 기대: 에러 0 (ed91a36 이전 상태)
- 실제: `ProfileScreen.test.tsx:17`, `ProfileEditScreen.test.tsx:17` TS2698
- 의심: `const actual = jest.requireActual('@react-navigation/native');` → `unknown` 타입 스프레드.
  `jest.requireActual<typeof import('@react-navigation/native')>(...)` 로 제네릭 지정하거나
  `Object.assign` 사용하면 해소될 것으로 보임 (수정은 frontend-agent).
- 넘길 대상: reading-record-frontend-agent

### BUG-20260827-03  `local` 프로필 서버가 AWS 자격증명 없이는 기동 실패
- 심각도: **major** (문서화된 로컬 실행 명령이 클린 체크아웃에서 깨짐, 블랙박스 테스트 선행 차단)
- 영역: backend · 상태: **open**
- 재현: `backend/`에서 `.env` 없이 `gradle bootRun --args="--spring.profiles.active=local"`
- 실제: 컨텍스트 초기화 실패 —
  `Error creating bean 's3Presigner' ... NullPointerException: Access key ID cannot be blank.`
  `S3Config.s3Presigner()`가 기동 시점에 빈 accessKey로 `AwsBasicCredentials`를 만들며 폭발.
- 기대: 개발현황.md §12-3 "accessKey/secretKey가 비어 있어도 서버 기동 자체는 정상"
  → 현재 사실이 아님 (해당 주장은 Gradle 미실행 상태로 작성됐고 실제 검증된 적 없음).
- 테스터 워크어라운드: `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY`에 더미값 주입 후 기동됨
  (테스트 `application.yml`도 더미값을 쓰고 있어 동일 방식).
- 제안(수정은 backend-agent): `S3Presigner` 빈을 `@Lazy` 또는 자격증명 없을 때 지연 생성,
  혹은 자격증명 없으면 `S3Presigner` 없이 뜨고 presigned-url 호출 시점에만 실패하도록.
- 넘길 대상: reading-record-backend-agent

### FINDING-20260827-04  ShareRecord API enum 대소문자 계약 불일치
- 심각도: **major** (프론트 연동 시 문서대로 소문자로 보내면 전부 400)
- 영역: backend (+ docs) · 상태: **open**
- 사실:
  - `POST /api/share-records`의 `shareType`/`scope`/`platform`(그리고 `targets[].targetType`)은
    JSON에서 **enum 이름 그대로(UPPERCASE)** 만 받는다: `"BOOK"`, `"ALL"`, `"INSTAGRAM"`.
    소문자 `"book"` 등은 `HttpMessageNotReadableException` → 400.
  - 응답 직렬화도 UPPERCASE (`"shareType":"BOOK"`).
  - 반면: DB에는 소문자로 저장(`ShareTypeConverter` 등), `Book.status` 쿼리 파라미터는
    대소문자 무관, `Genre`는 한글 라벨(`@JsonValue`), 개발현황.md §13은 API를 소문자
    (`book`/`dashboard`/`all`/`instagram`)로 서술.
  - 즉 enum이 코드베이스 안에서 4가지 방식으로 제각각 직렬화됨.
- 영향: **확인됨** — `frontend/src/types/share.ts`는 `ShareScope = 'all'|'group'|'custom'`,
  `SharePlatform = 'app'|'instagram'|'threads'|'tiktok'` 로 **소문자**를 쓴다. 프론트가 이 타입
  그대로 `POST /api/share-records`를 호출하면 100% 400. 연동 착수 전에 반드시 정리돼야 함.
- 제안(수정은 backend-agent): share enum들에도 `Genre`처럼 `@JsonValue`/`@JsonCreator`(소문자)
  를 붙여 API 계약을 소문자로 통일 + 개발현황.md/Swagger 예시 정합화. 또는 최소한 문서를 대문자로 정정.
- 넘길 대상: reading-record-backend-agent

### 관찰 (버그 아님)
- **OBS-06** 요청 본문의 잘못된 enum 값(`Genre` 라벨 오타, 없는 `interests` 항목 등)이
  `400 MALFORMED_REQUEST` + 제네릭 메시지 "요청 본문을 읽을 수 없습니다" + 빈 `fieldErrors`로
  떨어짐. 상태코드는 맞지만 클라이언트가 어느 필드가 문제인지 알 수 없음. `@JsonCreator`가
  던지는 `IllegalArgumentException`을 `GlobalExceptionHandler`가 필드 단위로 매핑하면 개선됨.
- **OBS-01**(이월) 프론트 lint CRLF/prettier 440건 — `.gitattributes` 필요. frontend-agent.
- **OBS-02**(이월) `App.test.tsx` `enableScreens()` console.error — `__mocks__` 추가로 침묵 가능.

  자동 생성, 또는 `docs/test/`에 seed 스크립트 상시 비치. (backend-agent와 협의)
