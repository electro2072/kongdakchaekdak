## 🐛 BUG-20260909-23 — 등록한 책이 서버에 저장되지 않음 (재시작하면 사라짐)

- 심각도: **blocker** (S3 슬라이스 전체를 막음 — 앱 코어 기능)
- 영역: backend ↔ frontend (양쪽 확인 필요)
- 상태: open
- 재현 (4~5회 모두 동일):
  1. 로그인 → 일정 탭 "새 책 등록하기" → "1984" 검색 → 첫 결과 → 장르 "소설" → "서재에 등록하기"
  2. 성공 토스트 + BookDetail 이동 + 서재 목록 상단에 "1984" 표시됨
  3. `adb shell am force-stop com.kongdakchaekdak` → 재실행
  4. 서재("읽고 있는 책") → **"1984" 없음.** 기존 3권만.
- 관찰된 사실:
  - `POST /api/books` 는 **성공 응답**(2xx). `apiFetch`가 `response.ok` 검사 후 `BookResponse`를 파싱했고, 그 `id`로 BookDetail 이동이 됐음. 에러 로그·403·토스트 없음.
  - 등록 직후 BookDetail의 소감·장소사진 로딩(`GET /api/books/{id}/notes`·`/photos`)이 **성공**(빈 목록 표시) → 그 시점엔 서버에 book이 존재.
  - 재시작 후 `GET /api/books?userId={id}` 는 기존 3권만 반환, 새 책 누락. `서재 목록 조회 실패` 에러 없음(GET 자체는 성공).
  - 반복 등록해도 서버에 누적되지 않음(재시작마다 3권 그대로) → **커밋이 안 되거나, 읽기와 다른 위치/유저로 저장되는 것**으로 보임.
- 코드 확인 (근거, 단정 아님):
  - BE `BookService.create` = `@Transactional`, `bookRepository.save(book)`, `request.userId().equals(currentUserId)` 검사 통과해야 함(POST 성공했으므로 통과한 것). audit `BOOK_REGISTERED` 이벤트 기록.
  - BE `BookService.search(userId, null)` = `findByUserId(userId)` — 페이지네이션·정렬·limit 없음. 전량 반환.
  - FE `LibraryContext.addBook` → `libraryApi.createBook({userId: ProfileContext.userId, ...})`. `ProfileContext.userId` 는 `GET /api/auth/me` 응답 `.id`. `fetchBooks(userId)` 도 같은 값 사용.
  - BE `/api/auth/me` 의 id = `@AuthenticationPrincipal`(JWT sub). `create` 의 `currentUserId` 도 같은 principal. → **이론상 저장 userId == 조회 userId 여야 함.**
- 가설 (dev 확인 필요):
  1. **BE**: `@Transactional` 커밋이 실제로 안 됨(예: 예외 삼킴, 롤백, 별도 트랜잭션 경계) — 201은 나가지만 DB 미반영.
  2. **BE/FE**: book이 조회와 **다른 userId**로 저장됨.
  3. **인프라**: Railway 다중 인스턴스 / 읽기 캐시 / DB 커넥션 이슈.
- **권장 조치**: 백엔드가 Railway 로그에서 `BOOK_REGISTERED` audit 이벤트(= `currentUserId`, `bookId`)를 확인하고, MySQL에서 `SELECT * FROM books WHERE title='1984'` 로 실제 저장 여부·user_id 를 직접 조회. FE는 등록 시 `POST /api/books` 요청 바디의 `userId` 와 응답 `id`·`userId` 를 로그로 남겨 대조.
- 넘길 대상: reading-record-backend-agent (1차) + reading-record-frontend-agent (요청/응답 로깅)
