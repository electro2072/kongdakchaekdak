## 요약

**카카오 로그인은 에러 경로 + 해피패스 모두 실동작 확인.** 유효한 카카오 access token으로
`POST /api/auth/kakao` → 우리 앱 JWT 발급 → `/api/auth/me` 유저 확인 → 재로그인 시 중복 생성
없음까지 테스터가 직접 재현함.

단, **`gradle bootRun` 자체는 여전히 기동 실패**(BUG-03, `.env`의 AWS 키가 비어 `S3Presigner`
빈 생성 NPE). 카카오와 무관한 별개 이슈. 테스터는 `bootJar` + 더미 AWS 환경변수로 우회해 기동함.

## 기동 방법 (BUG-03 우회)

```
gradle bootJar -x test
KAKAO_CLIENT_ID=<.env 값> AWS_ACCESS_KEY_ID=dummy AWS_SECRET_ACCESS_KEY=dummy \
  AWS_S3_BUCKET=dummy AWS_S3_REGION=ap-northeast-2 \
  java -jar build/libs/kongdakchaekdak-backend-0.0.1-SNAPSHOT.jar --spring.profiles.active=local
```
- `.env`에는 `KAKAO_CLIENT_ID`(32자, 앱 ID 1502106)만 채워져 있고 AWS/구글/네이버는 비어 있음.
- `java -jar`로 직접 띄우면 `build.gradle.kts`의 `.env` 로더(`bootRun` 전용 `doFirst`)를 안 타므로
  환경변수를 테스터가 직접 통제 가능.

**닉네임이 랜덤인 이유** (설계된 동작): 카카오 앱의 닉네임 동의항목이 "선택 동의"이고, 콘솔
테스트 도구 토큰 발급 시 그 scope 동의가 안 실려 `properties.nickname == null` → 백엔드가
`RandomNicknameGenerator`로 폴백. 폴백 경로까지 검증된 셈. 실제 앱에서 사용자가 닉네임 제공에
동의하면 카카오 닉네임이 들어감.
