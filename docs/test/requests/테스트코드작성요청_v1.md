- 받는 사람: reading-record-backend-agent, reading-record-frontend-agent

- 상태: 초안 — 사용자 검토 후 각 개발 에이전트가 반영

테스터는 테스트 코드를 직접 쓰지 않습니다(역할 규칙). 대신 각 담당 에이전트가 아래 형식으로
자동화 테스트를 작성/유지해 주시면, 테스터는 그것을 실행·회귀 확인하고 부족한 케이스를
이 문서에 추가 요청으로 남기는 방식으로 협업합니다.

---

## 공통 원칙

1. **결정론적일 것.** 실제 네트워크 호출 금지, `Date.now()`/`Math.random()` 등 비결정 요소는
   주입 가능하게 하거나 고정. (백엔드는 이미 캡션 선택을 나머지 연산으로 결정론화한 선례 있음.)
2. **행위 1개 = 테스트 1개.** Arrange–Act–Assert 3단 구조, 이름만 봐도 무엇을 검증하는지 알 것.
3. **공개 계약을 검증.** 내부 구현 디테일이 아니라 입력→출력(HTTP 상태·JSON 필드, 화면에 보이는
   텍스트·네비게이션 결과)을 단언.
4. **깨진 계약은 반드시 컴파일/테스트 실패로 드러날 것.** DTO·생성자·enum 라벨이 바뀌면
   관련 테스트가 전부 갱신되어야 하며, 일부만 고쳐 커밋하지 말 것
   (2026-08-27 회귀: `Book(String genre)` → `Book(Genre)` 전환 때 테스트 3파일 누락되어
   `:compileTestJava` 전체가 깨짐 — [reports/2026-08-27.md](../reports/2026-08-27.md) 참고).
5. **새 엔드포인트/화면/분기를 추가하면 같은 커밋에 테스트도 포함.** (커밋-단위 규칙과 동일선상.)

## A. 백엔드 (JUnit 5 + Spring Boot Test)

### 구조 / 도구
- 기존 컨벤션 유지: `src/test/java/.../<도메인>/<X>ControllerTest.java`,
  `@SpringBootTest` + `MockMvc` + H2(`src/test/resources/application.yml`), 클래스에 `@Transactional`로 롤백.
- 외부 연동(카카오/구글/네이버 OAuthClient 등)은 `@MockBean`. S3Presigner는 로컬 서명만 하므로
  더미 자격증명으로 실 로직까지 검증(기존 `BookPhotoControllerTest` 방식 유지).
- 테스트명은 지금처럼 한글 스네이크(`토큰_없이_요청하면_401`) 또는 `@DisplayName` 한글. 혼용하지 말고
  도메인 파일 안에서는 한 방식으로 통일.

### 각 엔드포인트가 갖춰야 할 최소 케이스
| 케이스 | 조건 |
|---|---|
| happy path | 정상 요청 → 2xx + 응답 JSON 필드 단언(`jsonPath`) |
| 검증 실패 | 필수 누락 / 길이 초과 / enum 라벨 오류 → 400 + `{error,message}` 포맷 |
| 인증 | 토큰 없음 → 401 (공통 포맷) |
| 인가 | 타인 리소스 쓰기 → 403 `FORBIDDEN` (해당되는 경우) |
| 부재 | 없는 id → 404 |
| 충돌 | 중복 생성 → 409 (해당되는 경우) |
| 교차 필드 검증 | `@Valid` 하나로 표현 안 되는 규칙(예: shareType=BOOK이면 bookId 필수, group scope면 target 전부 group) → 400 `INVALID_REQUEST` |

### 픽스처
- 데이터는 엔티티 생성자/팩토리 메서드로 만든다(SQL 스크립트 X).
- 인증 토큰은 주입한 `JwtProvider`로 발급(`generateToken(userId)`), `Authorization: Bearer` 헤더로.
- 날짜·집계가 관련된 테스트(대시보드 등)는 기대값을 손계산해 주석으로 남기고 그 상수를 단언.

### 응답 계약
- 성공 응답은 DTO record 필드명을 `jsonPath("$.fieldName")`으로 명시적으로 확인
  (특히 enum은 직렬화 형태 — `Genre`는 한글 라벨 `"소설"`).
- 에러 응답은 항상 `$.error`(코드), `$.message` 두 필드 확인.

### 지금 시급한 것 (2026-08-27 리포트 기준)
- `DashboardControllerTest` / `PublicShareControllerTest` / `ShareRecordControllerTest`의
  `new Book(...)` 호출을 `Genre` 타입으로 수정해 `:compileTestJava` 복구.
- 이후 `gradle test` 그린 상태 확인.

## B. 프론트엔드 (Jest + React Native Testing Library)

### 구조 / 도구
- `__tests__/`가 `src/` 구조를 미러링. 파일명 `<대상>.test.ts(x)`.
- 컴포넌트/화면 테스트는 `@testing-library/react-native` 사용 권장(현재 미설치 —
  `react-test-renderer` 직접 사용 중). 도입 시 `devDependencies`에 추가하고 이 문서 갱신.
- 네이티브 모듈은 `__mocks__/`로 스텁: `react-native-config`(있음), `react-native-screens`,
  `lucide-react-native`, `react-native-svg` 등 필요한 것 추가.
- 렌더 헬퍼: 테마/네비게이션/Auth/Profile Provider를 감싸는 `renderWithProviders(ui)` 하나를
  `__tests__/helpers/`에 두고 화면 테스트가 공통으로 사용.

### 무엇을 테스트할지 (우선순위 순)
1. **순수 로직 — 최우선, 커버리지 높게**
   - `services/aladin/aladinApi.ts`, `services/kakao/kakaoApi.ts`: 원본 응답(고정 fixture JSON)
     → 공통 `Book` 매핑. `global.fetch`를 mock해서 파싱/변환만 검증.
   - `services/bookService.ts`: provider 선택(기본 알라딘, providerId 지정), 에러 전파.
   - `hooks/useBookSearch.ts`, `hooks/useDashboard.ts`: `renderHook`으로 상태 전이
     (idle→loading→success / →error).
   - `constants/profileOptions.ts`: 관심분야 라벨 배열이 백엔드 `Genre` 라벨 6종과 정확히 일치
     (계약 회귀 테스트 — 하드코딩된 기대 배열과 비교).
2. **화면 — "크래시 없이 + 핵심 요소 + 주 상호작용"**
   - 각 화면: `renderWithProviders(<Screen/>)` 후 주요 텍스트/라벨이 보이는지(`getByText`),
     주 버튼 탭(`fireEvent.press`)이 올바른 네비게이션/콜백을 부르는지(`navigation.navigate` mock 단언).
   - 폼(Signup, ProfileEdit): 입력 → 검증 문구, 칩 다중 토글, 제출 콜백 인자.
3. **네비게이션 그래프**
   - `RootNavigator`: `AuthContext` 값에 따라 AuthStack ↔ MainStack 전환.
   - 딥링크성 이동(BookDetail→Share with bookId) 파라미터 전달.

### 스타일
- 스냅샷 테스트는 최소화(레이아웃 회귀 감지용으로 1~2개만). 나머지는 명시적 단언.
- 구현이 아니라 사용자에게 보이는 것 기준으로 쿼리(`getByText`/`getByRole`/`getByLabelText`).

### E2E (나중에)
- 에뮬레이터 E2E는 사용자가 Android Studio 에뮬레이터(`android-studio-quail2-windows`)로 수동 확인 중.
- 자동 E2E 도입 시 Maestro(YAML, 러닝코스트 낮음) 또는 Detox 중 택1 — 별도 요청서로 논의.

## 반영 방식

- 각 에이전트가 자기 영역의 테스트를 작성/수정하고, 커밋 메시지 접두사는 각자 규칙대로
  (`[backend]` / `[frontend]`).
- 반영 후 이 문서 하단에 "vN 반영 완료 (커밋 해시)"를 테스터가 추가.
- 커버리지 목표(제안): 백엔드 컨트롤러/서비스 라인 70%+, 프론트 services·hooks 80%+.
