## 1. 시드 데이터 확인

`dashboard-seed.sql` / `fixtures/README.md` 잘 받았습니다. 리뷰 결과:

- **스키마 호환 문제 없음** — 오늘(2026-09-07) `users` 테이블에 `last_login_at` 컬럼을 추가했는데
  (비활성 사용자 인앱 알림 기능), 시드의 `INSERT INTO users(...)`는 이 컬럼을 명시하지 않아서
  그냥 `NULL`로 들어갑니다. nullable 컬럼이라 에러 없음 — 다만 유저 9001로 `/api/auth/me`를
  호출해서 확인하면 `daysSinceLastLogin`은 `null`로 나올 거예요(로그인 API를 거치지 않고
  SQL로 직접 넣은 유저라서 — 의도한 대로).
- `genre` 컬럼에 한글 라벨('소설','에세이' 등)을 직접 넣는 방식도 `Genre`/`GenreConverter`
  구현과 정확히 일치합니다.

## 2. "5. 이 시드로 확인해볼 만한 것" — 코드 리뷰로 확인함

로컬에서 직접 서버를 못 띄워봐서(이 세션은 컴퓨터에 파일만 주고받을 수 있어 `gradle bootRun`
실행은 못 함) 실제 실행 대신 `DashboardService.java` 코드를 다시 읽어서 확인했습니다. 넷 다
의도대로 동작하는 게 맞습니다:

| 확인 항목 | 결과 |
|---|---|
| 분기 경계 (`date=2026-04` → Q2, `date=2026-07` → Q3) | ✅ `quarterStartMonth()`가 월→분기 시작월을 올바르게 계산 (4월→Q2 시작 4월, 7월→Q3 시작 7월). `periodStart`/`periodEnd`/`periodLabel` 모두 맞음 |
| 연간 `monthlyTrend`가 마지막 달 기준 직전 6개월 고정 | ✅ 맞음. 다만 한 가지 짚을 점 — YEAR의 `periodEnd`는 **항상 12/31**로 고정이라(오늘이 몇 월이든), trend는 항상 "7~12월"이 됨. 아직 안 지난 달(예: 지금 9월이면 10·11·12월)은 데이터가 없어 0으로 나오는 게 정상 — 시드 검증 결과의 `2·2·3·0·0·0`도 이 이유 |
| `totalPages`가 `null`인 책 합산 | ✅ `mapToLong(... == null ? 0L : ...)`으로 null-safe 처리됨 |
| 완독 기간 동률 tie-break (id 작은 쪽) | ✅ 최장/최단 둘 다 `Comparator`에 id 비교를 추가해뒀고, 둘 다 작은 id가 이기도록 구현됨 (최장은 `reverseOrder`로, 최단은 자연순서로 — 결과적으로 동일하게 작은 id 우선) |

## 3. 제안

동률 tie-break이랑 null totalPages 케이스는 지금 시드엔 없다고 하셨으니(README 참고), 여유
되면 시드에 "완독 기간이 같은 책 2권"이나 "totalPages가 NULL인 책 1권"을 추가해서 실제
API 응답으로 한 번 더 실행 확인해주시면 코드 리뷰 대신 실측으로 커버리지가 채워질 것 같아요.
급한 건 아니고, 지금 시드로도 기본 검증은 충분해 보입니다. 감사합니다!
