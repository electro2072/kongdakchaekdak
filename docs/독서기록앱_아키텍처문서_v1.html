콩닥책닥 백엔드 아키텍처

독서 기록을 남기고 공유하는 모바일 앱의 Spring Boot 백엔드 — REST API, 소셜 로그인 3사 연동, S3 이미지 업로드, 비로그인 공개 공유 웹뷰로 구성됩니다. 프론트엔드/디자인은 각 담당 에이전트의 별도 문서를 참고하세요.

범위와 한계. 이 문서는 백엔드(Spring Boot)만 다룹니다. 파일을 새로 읽지 않고, 이 대화 세션이 실제로 구현·검증한 내용만 근거로 작성했습니다. "지금 이 순간의 저장소"가 아니라 "이 세션이 알고 있는 최신 상태"의 스냅샷입니다.

01개요

사용자는 책을 검색해 등록하고, 사진·소감을 남기고, 독서 통계(대시보드)를 확인하고, 개별 책 또는 대시보드를 그룹/전체/커스텀 범위로 공유할 수 있습니다. 인증은 이메일/비밀번호 없이 소셜 로그인(카카오/구글/네이버)만 지원합니다 — 서버가 비밀번호 등 인증 정보를 직접 보관하지 않겠다는 제품 결정에 따른 것입니다. 이 백엔드(backend/)는 프로젝트 저장소 안의 한 영역이고, frontend/·design/은 각각 별도 에이전트가 담당합니다. 이 문서는 backend 담당 범위만 다룹니다.

03전체 시스템 구조

백엔드 관점에서 보면, Spring Boot 서버는 React Native 클라이언트의 REST 호출을 받고, 그와 별개로 두 종류의 외부 서비스(소셜 로그인 제공자, S3)를 서버가 직접 호출합니다. (도서 검색은 클라이언트가 외부 API를 직접 호출하며 백엔드를 거치지 않으므로 이 문서 범위 밖입니다.) 소셜 로그인은 서버가 인가 코드를 받는 방식이 아니라, 모바일 앱이 각 제공자 SDK로 이미 로그인해서 받은 토큰을 그대로 서버에 넘기고, 서버는 그 토큰으로 "누구세요?"만 물어보는 방식입니다 — 서버 쪽에는 Client Secret이 필요 없습니다.

04백엔드 도메인 구조

domain/ 아래 도메인별 패키지로 나뉘고, 각 도메인은 Controller → Service → Repository의 동일한 계층 구조를 따릅니다. 쓰기(수정/삭제) API는 ForbiddenException(403)으로 본인 소유가 아니면 거부하고, 조회 API는 공유 앱 특성상 의도적으로 열어둡니다.

05인증 흐름 — 소셜 로그인 + 신규/기존 판별

TokenResponse.isNewUser(2026-08-29 추가)가 프론트 분기의 핵심입니다. 신규 가입 시 닉네임은 카카오/네이버는 제공자 프로필 닉네임을 그대로 쓰고 없으면 랜덤 생성, 구글은 실제 이름이 아니라 이메일 주소가 들어가는 알려진 결함이 있습니다(§11).

06이미지 업로드 흐름

서버는 실제 파일 바이트를 한 번도 거치지 않습니다. presigned URL 발급은 로컬 서명 연산이라 AWS로 네트워크 요청조차 나가지 않습니다. S3Presigner 빈은 자격증명이 없어도 서버가 기동 실패하지 않도록 주입 지점까지 포함해 @Lazy 처리되어 있습니다(2026-08-28~29, BUG-20260827-03 대응 — 빈 정의뿐 아니라 BookPhotoService 생성자 파라미터에도 @Lazy를 붙여야 실제로 지연됨을 확인).

sequenceDiagram
    participant App as RN 앱
    participant API as BookPhotoController
    participant S3 as AWS S3

    App->>API: POST /photos/presigned-url
    API->>S3: 로컬 서명(네트워크 호출 없음)
    S3-->>API: 서명된 URL
    API-->>App: presigned URL + 공개 URL
    App->>S3: 파일 직접 PUT
    App->>API: POST /photos (공개 URL)
    API->>API: BookPhoto 레코드 생성

07공개 공유 웹뷰

ShareRecord 생성 시 항상 public_token(UUID)이 발급됩니다. 로그인 없이 /public/share/{token}으로 접근 가능하며, PublicShareViewService가 엔티티를 절대 템플릿에 넘기지 않고 완전히 평탄화한 뷰 레코드로 변환해 지연 로딩 문제를 원천 차단합니다. 대시보드 공유는 공유 시점에 스냅샷으로 얼려 저장한 JSON을 보여줍니다 — 나중에 데이터가 바뀌어도 공유 당시 숫자가 그대로 보이게 하기 위함입니다.

09횡단 관심사

로깅

LogType(ACCESS/SECURITY/AUDIT/ERROR/APPLICATION) 5종을 파일로 나누지 않고 stdout + MDC(traceId/logType)로 구분 — Railway 컨테이너 파일시스템이 휘발성이라 파일 appender는 local 프로필에서만 켭니다.

예외 처리

GlobalExceptionHandler가 도메인 예외와 HttpMessageNotReadableException을 공통 ErrorResponse JSON으로 변환합니다. catch-all 핸들러도 있어 미처리 예외도 동일 포맷 500으로 나갑니다.

enum ↔ JSON 계약

Genre·ShareType·ShareScope·SharePlatform·ShareTargetType은 @JsonValue/@JsonCreator로 API 계약을 고정하고, DB 매핑은 별도 @Converter로 독립 처리합니다. DashboardPeriod는 아직 이 패턴이 빠져 대문자만 허용되는 불일치가 남아 있습니다.
