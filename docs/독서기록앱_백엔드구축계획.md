## 1. 기술 스택

| 영역 | 선택 | 비고 |
|---|---|---|
| 언어 | Java (또는 Kotlin 검토) | 회사에서 Java 사용 중이므로 Java로 우선 시작 |
| 프레임워크 | Spring Boot 3.x | |
| 빌드 도구 | **Gradle** (Kotlin DSL) | Maven 대비 최신 표준, 빌드 속도 빠름, 회사 Maven 경험과 개념 호환 |
| ORM | Spring Data JPA (Hibernate) | 테이블정의서 → Entity 매핑 |
| DB | MySQL | 초기엔 로컬 Docker로 구성 |
| 인증 | Spring Security + JWT | 소셜 로그인(네이버/카카오/구글) OAuth2 연동 |
| API 문서 | Swagger (springdoc-openapi) | 프론트(RN)와 스펙 공유용 |
| 이미지 저장 | AWS S3 (또는 Firebase Storage) | BookPhoto, 프로필 이미지, 표지 이미지, 공유 카드 이미지 |
| 카드 이미지 생성 | 서버사이드 렌더링 (예: HTML→이미지 변환) 또는 프론트에서 캡처 후 업로드 | 4번 항목 참고, 방식은 Step 5에서 결정 |
| 공개 웹뷰 | Thymeleaf 또는 별도 정적 페이지 + OG 메타태그 | 인증 없이 접근 가능한 서버 렌더링 페이지 |
| 배포 | 로컬 → ngrok(초기 연동 테스트) → AWS EC2 + RDS (또는 Railway) | 단계적 확장 |

- **Like / Comment / Follow 관련 패키지는 만들지 않음** (Frame 04 변경사항 반영, 설계 범위 제외 확정)

## 3. 엔티티 설계 매핑 (테이블정의서 기준 + 신규 변경분)

| 테이블 | 우선순위 | 비고 |
|---|---|---|
| User | 1순위 | 소셜 로그인 붙기 전엔 임시 로그인(이메일/PW)으로 먼저 CRUD 검증. **`gender` 컬럼 추가** |
| Interest / UserInterest | 1순위 (신규) | 회원가입 시 관심 분야 다중 선택 저장용, User와 함께 진행 |
| Book | 1순위 | 프론트 책 검색 컴포넌트가 이미 있어 바로 연동 테스트 가능 |
| BookPhoto | 2순위 | 이미지 업로드(S3) 붙은 뒤 진행. 공유 카드 생성 시 사용자가 선택한 사진(N장) 참조용으로도 쓰임 |
| BookNote | 2순위 | Book CRUD 이후 |
| Group / GroupMember | 3순위 | 공유 탭 기능과 함께. **회원가입 시 "속한 독서모임" 추가도 GroupMember 재사용** (신규 테이블 불필요) |
| ShareRecord / ShareRecordTarget | 3순위 | **`share_type`, `card_image_url`, `public_token` 컬럼 추가** (4번 항목) |
| ~~Like~~ / ~~Comment~~ / ~~Follow~~ | 제외 | Frame 04 변경으로 설계 범위에서 완전히 제외 |

### 3-1. 신규/변경 테이블 상세

**User (컬럼 추가)**

| 컬럼명 | 타입 | NULL | 설명 |
|---|---|---|---|
| gender | VARCHAR(10) | Y | MALE / FEMALE / NONE (선택 안 함 기본) |

**Interest (신규 — 관심 분야 마스터)**

| 컬럼명 | 타입 | 설명 |
|---|---|---|
| id | BIGINT (PK) | |
| name | VARCHAR(30) | 소설, 에세이, 자기계발, 인문, 과학, 경제·경영, 예술, 시 등 |

**UserInterest (신규 — 다대다 매핑)**

| 컬럼명 | 타입 | 설명 |
|---|---|---|
| id | BIGINT (PK) | |
| user_id | BIGINT (FK → User.id) | |
| interest_id | BIGINT (FK → Interest.id) | user_id + interest_id 유니크 |

**ShareRecord (컬럼 추가)**

| 컬럼명 | 타입 | NULL | 설명 |
|---|---|---|---|
| share_type | VARCHAR(20) | N | `book`(독서 기록 공유) / `dashboard`(대시보드 공유) |
| card_image_url | VARCHAR(255) | Y | 생성된 공유 카드 이미지 URL (S3) |
| public_token | VARCHAR(64) | Y | 공개 웹뷰 접근용 UUID 토큰, 비로그인 사용자도 이 값으로 접근 |

> `share_type`이 `book`이면 `book_id` 참조, `dashboard`면 기간(period)·통계 스냅샷을 함께 저장할지는 Step 5에서 상세 설계 (매번 실시간 재계산 vs 스냅샷 저장 트레이드오프 검토 필요)

## 5. API 설계 초안 (예시)

| Method | Endpoint | 설명 |
|---|---|---|
| POST | `/api/auth/login` | 로그인 (초기: 이메일/PW, 이후 OAuth2) |
| POST | `/api/users` | 회원가입 (닉네임 · 성별 · 관심분야 · 독서모임 포함) |
| GET | `/api/users/me` | 내 정보 조회 |
| GET | `/api/interests` | 관심 분야 마스터 목록 조회 (회원가입 화면 태그 노출용) |
| POST | `/api/books` | 책 등록 (일정 탭) |
| GET | `/api/books?status=reading` | 진행 중/완독 책 목록 조회 |
| PATCH | `/api/books/{id}/complete` | 완독 처리 |
| POST | `/api/books/{id}/photos` | 장소 사진 등록 |
| POST | `/api/books/{id}/notes` | 소감 등록 |
| **GET** | **`/api/dashboard?period=quarter&date=2026-07`** | **(신규) 기간별 독서 대시보드 통계 조회** |
| **POST** | **`/api/share-records`** | **공유 기록 생성 (`shareType: book \| dashboard`, 카드 이미지 생성 트리거)** |
| **GET** | **`/public/share/{token}`** | **(신규, 비인증) 공유 카드 공개 웹뷰 — OG 태그 포함 HTML 반환** |

> 상세 요청/응답 DTO는 각 Step 진행하며 Swagger로 구체화 예정
> ~~좋아요/댓글/팔로우 API~~는 화면설계서 변경으로 설계에서 제외

## 6. 참고 사항

- 프론트는 현재 Frame 03의 책 검색 컴포넌트까지 구현 완료된 상태 → **Book API를 최우선으로 개발해 바로 연동 테스트하는 것을 목표**로 함
- 회사에서 Maven 경험이 있으나, 신규 프로젝트는 Gradle로 진행 (개념은 동일하여 전환 부담 적음)
- 상태관리 라이브러리 미사용 등 프론트 결정사항과 마찬가지로, 백엔드도 초기엔 최소 구성으로 시작 후 필요 시 확장
- **대시보드 통계는 별도 테이블 없이 Book 데이터를 실시간 집계하는 방식으로 우선 설계** — 사용자·데이터가 늘어나 성능 이슈가 생기면 그때 캐싱/배치 집계 테이블 도입 검토
- **공개 웹뷰(`/public/share/{token}`)는 인증 예외 경로이므로 Step 3 인증 설계 시 반드시 함께 고려** — 나중에 붙이면 놓치기 쉬운 부분
- `독서기록앱_테이블정의서.xlsx`는 아직 이번 변경사항(User.gender, Interest, UserInterest, ShareRecord 컬럼 추가) 반영 전 — 필요 시 별도로 업데이트 요청 주세요
