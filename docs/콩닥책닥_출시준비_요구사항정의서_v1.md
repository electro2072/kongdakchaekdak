## A. 기능 요구사항 (개발 필요)

### R-01. 회원 탈퇴 〔P0 · iOS 심사 블로킹〕
- **근거**: Apple Guideline 5.1.1(v) — 계정 생성 앱은 앱 내 계정 삭제 필수. 공개 문서 3종(약관·방침·계정삭제안내)이 이미 이 기능을 전제함.
- **상세**: 별도 요청서 **`콩닥책닥_기능추가요청_회원탈퇴_v1.md`** 참조 (역할별 TODO·삭제 스펙·수용 기준 5개 포함).
- **담당**: 기획 + 디자인 + 프론트 + 백엔드
- **완료 기준**: 요청서 5장 수용 기준 전부 통과

### R-02. 게시물 신고 〔P0 · iOS 심사 블로킹 (UGC)〕
- **근거**: Apple Guideline 1.2 — UGC 앱은 부적절 콘텐츠 신고 수단 필수. 이용약관 제10조가 "신고 접수 후 24시간 내 조치"를 공지함.
- **범위**: 그룹/공유로 타인에게 보이는 콘텐츠(공유 기록, 그룹 게시물)에 신고 진입점. 신고 사유 선택(음란/혐오/스팸/권리침해/기타) → 운영자에게 전달(초기엔 이메일 알림 또는 관리자 조회 API로 충분).
- **담당**: 기획(사유 분류·처리 프로세스) + 디자인(신고 진입점 — 기존 액션 시트 컴포넌트 재사용 가능, Frame 03.2 패턴) + 프론트 + 백엔드(신고 테이블·API)
- **완료 기준**: ① 타인 콘텐츠에서 3탭 이내로 신고 가능 ② 신고 내역이 서버에 저장되고 운영자가 확인 가능 ③ 처리(삭제/기각) 상태 기록 가능

### R-03. 사용자 차단 〔P0 · iOS 심사 블로킹 (UGC)〕
- **근거**: Apple Guideline 1.2 — 불쾌한 사용자를 차단하는 수단 필수. 이용약관 제10조 3항이 차단 기능을 공지함.
- **범위**: 그룹 멤버/공유 상대 프로필에서 차단 → 차단한 상대의 콘텐츠 미표시. 차단 목록 조회·해제(설정 내).
- **담당**: 기획 + 디자인 + 프론트 + 백엔드
- **완료 기준**: ① 차단 시 상대 콘텐츠가 즉시 숨겨짐 ② 설정에서 차단 목록 확인·해제 가능
- **비고**: R-02와 같은 화면·같은 액션 시트에 배치되므로 **한 스프린트로 묶어 진행 권장**

### R-04. Sign in with Apple 〔P0 · iOS 출시 시점 블로킹〕
- **근거**: Apple Guideline 4.8 — 제3자 소셜 로그인 제공 앱은 Apple 로그인 병행 필수. Android 출시에는 불필요.
- **범위**: 로그인 화면에 Apple 버튼(iOS만 노출) · identityToken 서버 검증(구글 idToken 검증 로직 재활용) · provider enum `APPLE` 추가.
- **주의**: ① 이름·이메일은 **최초 로그인 1회만** 내려옴 — 첫 응답에서 반드시 저장 ② "이메일 가리기" 릴레이 주소 허용 ③ Apple Developer Program 가입(N-01) 선행 필요.
- **담당**: 프론트 + 백엔드 (+ 디자인: 버튼 1종 — Apple 공식 가이드 스타일 준수)
- **완료 기준**: iOS에서 Apple 계정으로 신규 가입·재로그인·탈퇴 후 재가입이 모두 동작
- **예상 규모**: 프론트+백 합산 1~2일

### R-05. 사진 촬영 장소 남기기 (위치) 〔P1 · 신고 정합성 주의〕
- **근거**: 확정된 기획(2026-09-08, "갬성" 기능). Info.plist 위치 문구·PrivacyInfo·매핑표가 이미 이 기능 기준으로 작성됨.
- **제약**: 스토어 신고에서 위치를 **"선택(Optional)"** 으로 신고했으므로, 구현도 반드시 **사용자가 원할 때만 동작하는 선택 액션**이어야 함(자동 수집 금지). 권한 팝업은 "장소 남기기"를 처음 누르는 시점에 요청.
- **담당**: 기획(F-05 명세 추가) + 디자인 + 프론트 + 백엔드
- **완료 기준**: ① 장소 없이도 기록 저장 가능 ② 장소 남기기 선택 시에만 권한 요청·좌표 저장 ③ 기록에서 장소 삭제 가능

## B. 비기능·운영 요구사항 (개발 아님)

### N-01. 개발자 계정 등록 〔P0〕
- Apple Developer Program $99/년 · Google Play Developer $25(1회). **R-04와 스토어 콘솔 입력 전체의 선행 조건.**
- 담당: 운영자

### N-02. Android 서명 준비 〔P0〕
- 업로드 키스토어 생성·백업, Play App Signing 등록, 카카오 키 해시·구글 SHA-1(release) 각 콘솔 등록.
- 담당: 프론트(빌드 담당) · 완료 기준: release AAB가 서명되어 Play Console 업로드 성공

### N-03. 테스트 구글 계정 생성·시딩 〔P0〕
- `콩닥책닥_심사용_데모계정_안내_v1.md` 2~3장 체크리스트 실행 (2단계 인증 해제, 사전 로그인, 데모 데이터 시딩). 완료 후 문서의 〔기입〕란 채우기.
- 담당: 운영자 + 백엔드(시드 지원)

### N-04. 네이버 로그인 검수 신청 〔P0 — 네이버 로그인을 출시 버전에 포함할 경우〕
- 검수 승인 전엔 등록자 본인만 로그인 가능. 검수에 개인정보처리방침 URL 필요 → 저장소 커밋 후 즉시 신청 가능.
- **대안**: 검수 일정이 늦어지면 1차 출시에서 네이버 버튼을 숨기고 P1로 미루는 것도 가능 — PM 결정 필요.
- 담당: 운영자

### N-05. 스토어 콘솔 입력 〔P0 · N-01 이후〕
- `콩닥책닥_데이터수집신고_매핑표_v1.md` 3장 체크리스트 순서대로: Data safety 7항목 → 계정 삭제 URL → App Privacy 6항목 → 스토어 텍스트/스크린샷 업로드(`콩닥책닥_스토어등록텍스트_v2.md`) → IARC 콘텐츠 등급 설문.
- 담당: 운영자 (매핑표 보고 클릭만 하면 됨)

### N-06. 기획서 정합화 〔P1〕
- F-09에 회원 탈퇴, F-05에 장소 남기기, 신규 기능ID(신고 F-13 / 차단 F-14 제안) 추가. 〔확정 필요〕 49곳 중 출시 관련 항목 우선 소거.
- 담당: 기획

## C. 의존 관계와 권장 순서

```
N-01 계정 등록 ──┬─→ R-04 Apple 로그인 ──┐
                └─→ N-05 콘솔 입력 ←── N-02 서명 · N-03 테스트계정      │
R-01 탈퇴 ─┬────────────────────────→ 심사 제출 ←──┘
R-02+R-03 신고·차단 ─┘        (N-04 네이버 검수는 병렬)
R-05 위치는 P1 — 심사 제출을 막지 않음 (단, 미구현 상태로 오래 두면
       위치 신고를 이미 해둔 상태와 어긋나므로 출시 직후 1~2 스프린트 내 구현)
```

**요약**: 개발 P0는 R-01·R-02·R-03(+iOS면 R-04) 네 개. 나머지는 운영자 액션.
