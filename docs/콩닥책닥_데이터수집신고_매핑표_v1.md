## 1. Google Play — Data safety 양식

콘솔 경로: `앱 콘텐츠(App content) → 데이터 보안(Data safety)`

### 1-1. 개요 질문

| 콘솔 질문 | 답 |
|---|---|
| 앱이 필수 사용자 데이터를 수집하거나 공유하나요? | **예 (수집함)** |
| 수집한 데이터가 전송 중에 암호화되나요? | **예** |
| 사용자가 데이터 삭제를 요청할 수 있는 방법을 제공하나요? | **예** — 앱 내 계정 탈퇴 기능 |

### 1-2. 데이터 유형별 답안

공통 답: **공유 안 함(Not shared) · 처리 목적 = 앱 기능(App functionality) · 필수/선택은 아래 표 참고**

| Play 카테고리 → 세부 항목 | 수집? | 필수/선택 | 근거 |
|---|---|---|---|
| 위치 → **정확한 위치(Precise location)** | 수집함 | **선택** (장소 남기기를 쓸 때만) | 사진 촬영 장소 좌표 (PRIVACY 1-2) |
| 개인 정보 → **이름(Name)** | 수집함 | 필수 | 닉네임 (PRIVACY 1-2) |
| 개인 정보 → **이메일 주소(Email address)** | 수집함 | 선택 (구글 로그인 이용자만) | PRIVACY 1-1 |
| 개인 정보 → **사용자 ID(User IDs)** | 수집함 | 필수 | 소셜 로그인 고유 식별자 (PRIVACY 1-1) |
| 사진 및 동영상 → **사진(Photos)** | 수집함 | 선택 | 책 사진 업로드 (PRIVACY 1-2) |
| 앱 활동 → **기타 사용자 제작 콘텐츠(Other user-generated content)** | 수집함 | 필수 | 독서 기록·소감·별점·프로필 소개 (PRIVACY 1-2) |
| 앱 정보 및 성능 → **진단(Diagnostics)** | 수집함 | 필수 | 접속 로그·보안 이벤트 기록 (PRIVACY 1-3) |

### 1-3. "수집 안 함"으로 두는 항목 (체크하지 말 것)

금융 정보 · 건강 및 피트니스 · 메시지 · 오디오 · 파일 및 문서 · 캘린더 · 연락처 · 웹 검색 기록 · 브라우징 기록 · 기기 또는 기타 ID(광고 ID)
— 전부 미수집 (PRIVACY 1-3에서 명시적으로 부인)

### 1-4. 계정 삭제 관련 (Play 요구사항)

- "계정 생성이 가능한가?" → **예 (소셜 로그인)**
- 계정 삭제 URL 제출 필요 → **웹 페이지가 아직 없음.** 임시로 저장소 내 안내 문서 URL 사용 가능하나, 심사 기준상 "웹에서 접근 가능한 삭제 안내"가 필요하므로 **계정 삭제 안내 페이지 제작이 남은 과제** (배포 필요문서 목록 #7).

## 2. App Store — App Privacy 설문

콘솔 경로: `App Store Connect → 앱 → App Privacy`

첫 질문 "이 앱에서 데이터를 수집합니까?" → **예**

### 2-1. 데이터 유형별 답안

모든 항목 공통 답:
- 사용 목적: **App Functionality (앱 기능)**
- **사용자 신원과 연결됨(Linked to the user): 예** (계정 기반 서비스이므로)
- **추적 목적 사용(Used for tracking): 아니오**

| App Store 카테고리 → 세부 항목 | 수집? | PrivacyInfo 선언과 대응 |
|---|---|---|
| 연락처 정보 → **이름(Name)** | 예 | `NSPrivacyCollectedDataTypeName` |
| 연락처 정보 → **이메일 주소(Email Address)** | 예 | `NSPrivacyCollectedDataTypeEmailAddress` |
| 식별자 → **사용자 ID(User ID)** | 예 | `NSPrivacyCollectedDataTypeUserID` |
| 위치 → **정확한 위치(Precise Location)** | 예 | `NSPrivacyCollectedDataTypePreciseLocation` |
| 사용자 콘텐츠 → **사진 또는 동영상(Photos or Videos)** | 예 | `NSPrivacyCollectedDataTypePhotosorVideos` |
| 사용자 콘텐츠 → **기타 사용자 콘텐츠(Other User Content)** | 예 | `NSPrivacyCollectedDataTypeOtherUserContent` |

### 2-2. "수집 안 함"으로 두는 항목

건강 및 피트니스 · 금융 정보 · 연락처(주소록) · 검색 기록 · 브라우징 기록 · 구입 항목 · 광고 데이터 · 진단(크래시 리포트 툴 도입 전까지) · 기타 데이터

> ⚠️ 참고 — 진단 항목 비대칭: Google Play에는 접속 로그를 "진단"으로 신고하지만, App Store의 "진단(Diagnostics)"은 크래시·성능 데이터를 뜻하는 좁은 개념이라 서버 접속 로그는 해당하지 않음. PrivacyInfo에도 진단 유형은 선언하지 않았으므로 App Store 쪽은 "수집 안 함" 유지가 일관된 답. 추후 Crashlytics 등 도입 시 양쪽 모두 갱신할 것.

### 2-3. 향후 변동 트리거

| 앱에 이런 변화가 생기면 | 설문에서 바꿀 것 |
|---|---|
| 크래시 리포트 도구(Crashlytics/Sentry) 도입 | 진단(Diagnostics) 추가 — 양 스토어 + PrivacyInfo |
| 광고 도입 | 추적·광고 항목 전면 재작성 + ATT 팝업 필요 (사실상 새 신고) |
| Apple 로그인 추가 (예정) | 변경 없음 — 이미 이름·이메일·사용자 ID 선언에 포함됨 |
| 푸시 알림(F-12) 구현 | 변경 없음 — 푸시 토큰은 별도 신고 항목 아님 (기기 ID 아님) |

## 3. 콘솔 입력 순서 (실전 체크리스트)

1. [ ] Google Play Console → 앱 콘텐츠 → 데이터 보안 → 1-1 개요 3문항 답변
2. [ ] 1-2 표의 7개 항목 체크 (각각 수집함 · 공유 안 함 · 앱 기능 · 필수/선택 구분)
3. [ ] 계정 삭제 URL 입력 (⚠️ 페이지 제작 선행 필요)
4. [ ] App Store Connect → App Privacy → 2-1 표의 6개 항목 체크 (전부 연결됨 · 추적 아니오 · 앱 기능)
5. [ ] 제출 전 최종 대조: 이 문서 ↔ PRIVACY.md ↔ PrivacyInfo.xcprivacy
