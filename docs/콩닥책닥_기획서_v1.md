## 2. 서비스 개요

### 2.1 한 줄 정의
읽은 책을 간단히 기록하고, 친구·그룹 또는 SNS에 자랑처럼 공유하는 모바일 앱.

### 2.2 기획 배경 / 문제 정의

**배경**
- 자기 기록·공유 문화가 일상화됐다("오운완"으로 운동을 인증하듯).
- 병렬 독서가 확산되고, 서울국제도서전이 흥행하며, '텍스트 힙'이라 불릴 만큼 읽기가 하나의 취향 표현이 됐다.
- 독서도 자랑과 공유의 대상이 되는 분위기다.

**문제**
1. 무슨 책을 언제부터 언제까지 읽었는지 남기지 않으면 잊는다. 그때의 감상도 함께 사라진다.
2. 글귀를 적고, 사진을 찍고, 소감을 다듬는 과정이 번거로워 기록이 지속되지 않는다.
3. 독서 모임에서 소감과 모임 장소를 공유하지만, 오픈채팅은 대화가 흘러가 축적되지 않는다.
4. 분기·연간 단위로 내가 얼마나 읽었는지 돌아볼 수단이 없다.

**기존 대안의 한계**
- YES24·교보 등 서점 앱에도 기록 기능이 있으나 구매처에 종속된다. 독자는 한 곳에서만 책을 사지 않는다. 콩닥책닥은 구매처와 무관하게 하나의 서재에 모아준다.

### 2.3 해결 가설
- 기록 작성을 앱이 최대한 대행한다: 책 검색으로 표지·서지정보(제목·저자·ISBN·쪽수)를 자동 입력하고, 사진·소감·기간을 한 흐름에서 남긴다.
- 세 가지 핵심 행동을 끊김 없이 잇는다.
  1. **기록** — 시작과 완독을 남긴다.
  2. **자랑(공유)** — 우리끼리(그룹) 또는 모두에게(SNS) 공유한다.
  3. **리캡** — 기간별로 읽은 양과 취향을 돌아본다.

### 2.4 목표 & 성공 지표(KPI)

〔확정 필요 — 아래는 제안값〕

| 구분 | 목표 | 측정 지표 | 목표치 | 측정 시점 |
|---|---|---|---|---|
| 정성 | 기록이 부담스럽지 않다고 느낀다 | 스토어 리뷰·인앱 설문 긍정 비율 | 70% | 출시 +3개월 |
| 정량 | 첫 기록 작성 전환 | 가입 후 7일 내 기록 1건 이상 작성한 사용자 비율 | 40% | 출시 +1개월 |
| 정량 | 리텐션 | 가입 4주차 잔존율 | 20% | 출시 +2개월 |
| 정량 | 공유 활성 | 기록 작성자 중 월 1회 이상 공유한 사용자 비율 | 30% | 출시 +2개월 |

## 3. 타겟 사용자

### 3.1 핵심 타겟
- **연령대**: 20~40대
- **성별**: 여성 비중이 높을 것으로 예상한다. 〔확정 필요 — 국내 독서 인구 통계 등 근거 보강〕
- **독서량**: 무관. 연 2~3권의 라이트 리더도 핵심 타겟이다.
- **기존에 쓰는 도구**: 서점 앱의 기록 기능, 인스타그램·블로그 독서 기록, 노션·엑셀 표.

### 3.2 페르소나

**페르소나 A — 홍연수 (31, 회사원)**
- 독서 습관: 연 2~3권. 서울국제도서전 방문 후 "더 읽자"고 결심했다.
- 니즈: 읽은 책과 그때의 감상을 남기고 싶다.
- 현재 불편: 기록하지 않아 무엇을 읽었는지, 어떤 마음이었는지 잊는다.
- 콩닥책닥으로: 완독 직후 소감을 빠르게 남기고, 분기 리캡으로 돌아본다.

**페르소나 B — 김도영 (34, 직장인)** 〔이름·나이 확정 필요〕
- 상황: 매주 지정 도서로 만나는 오프라인 독서 모임에 참여한다.
- 니즈: 모임 전 소감을 미리 정리·시각화해 공유하고, 모임 장소도 공유한다. 단 모임 멤버에게만.
- 현재 불편: 오픈채팅 공유는 대화가 흘러가 기록이 남지 않는다.
- 콩닥책닥으로: 그룹 비공개 공유로 소감 카드와 장소를 남긴다.

### 3.3 사용 시나리오
1. **완독 직후 기록** — 한강 작가의 책을 하루 만에 완독한다. 기억이 사라지기 전에 앱을 열어 소감을 남긴다. 친구와 한강공원에서 읽었고 날씨가 좋아 찍은 하늘 사진도 함께 첨부한다.
2. **구매 직후 등록** — 교보문고에서 눈에 띈 책을 산다. 책장에 꽂으면 잊으므로, 바로 앱을 열어 "읽는 중" 또는 "읽을 예정"으로 등록한다.

## 5. 서비스 컨셉 & 핵심 가치

### 5.1 컨셉 키워드 / 톤&무드
- **이름**: 콩닥책닥. 책거리(册禮) 때 콩송편을 나눠 먹던 전통과, 설렘의 "콩닥콩닥"을 겹친 이름.
- **톤**: 오래 봐도 눈이 편한 쑥색(쑥송편 그린) 기반. 차분하고 아늑하게.
- **브랜딩**: 송편 모티프의 앱 아이콘 시안은 폐기(deprecated)했고, 워드마크 배지 방식으로 확정했다.
- 디자인 시스템(연두 테마, 라이트/다크)과 톤을 일치시킨다.

### 5.2 핵심 가치 (3개)
기능 우선순위는 이 세 가지를 기준으로 가른다.
1. **기록한다** — 무엇을, 언제부터, 어떻게 읽었는지 남긴다. (서재)
2. **자랑한다** — 시작도 완독도, 우리끼리(그룹) 또는 모두에게(SNS) 공유한다. (공유)
3. **돌아본다** — 분기·연간 단위로 읽은 양과 취향을 리캡으로 확인한다. (리캡)

### 5.3 하지 않을 것 (Non-goals)
- 자체 이메일/비밀번호 회원가입을 만들지 않는다. 가입·인증은 전부 소셜 로그인(카카오·구글·네이버)으로 처리한다.
- 앱 내 도서 판매·결제를 하지 않는다. 〔확정 필요〕
- 전자책 뷰어 기능을 제공하지 않는다. 〔확정 필요〕
- 낯선 사람과의 팔로우·피드형 SNS를 이번 버전에서 만들지 않는다. 공유는 링크와 그룹 중심이다. 〔확정 필요〕

## 7. 기능 상세 명세

> 실제 백엔드 구현값을 반영했다. 미정 항목은 〔확정 필요〕로 표시한다.

### F-01. 소셜 로그인 / 온보딩
- **목적 / 사용자 가치:** 비밀번호 없이 몇 초 안에 시작한다.
- **진입 경로:** 앱 최초 실행 · 로그아웃 후 · 세션 만료 시.
- **상세 동작:**
  1. 네이버 → 카카오 → 구글 순서로 로그인 버튼을 노출한다.
  2. 버튼 탭 → 각 SDK 인증 → 백엔드에 소셜 액세스 토큰(구글은 idToken) 전달 → 서버 검증 후 JWT 발급.
  3. 신규 사용자는 회원가입(F-02)으로, 기존 사용자는 일정 탭으로 이동한다.
  4. "비회원으로 둘러보기"는 로그인 없이 읽기 전용으로 탐색하며, 기록·공유 시도 시 로그인을 유도한다.
- **정책·규칙:** 이메일/비밀번호 가입 없음. 소셜 `(provider, social_id)` 조합당 1개 회원. 제공자 간 계정 통합 미지원 〔확정 필요〕.
- **예외·에러:** SDK 인증 취소 → 원화면 유지. 서버 검증 실패 → "다시 시도" 안내. 네트워크 오류 → Frame 09.
- **관련:** Frame 01 · `POST /api/auth/social/*` · `User`

### F-02. 회원가입 (최소 정보)
- **목적 / 사용자 가치:** 최소 정보만 받아 이탈을 줄인다.
- **진입 경로:** F-01에서 신규 사용자로 판별된 직후.
- **상세 동작:**
  1. 닉네임(필수, 1~30자) 입력 → 실시간 중복 검사.
  2. 성별(여성/남성/선택 안 함, 기본 "선택 안 함"), 관심 분야(6종 다중 선택), 소속 독서모임(그룹 검색 후 연결) — 모두 선택.
  3. "시작하기" → `User` 생성 + 관심분야·`GroupMember` 매핑 → 일정 탭.
- **정책·규칙:** 닉네임 유일성 보장, 금칙어 필터 〔확정 필요〕. 관심 분야는 고정 6종(소설·에세이·자기계발·인문·과학·경제·경영). 이후 프로필 편집에서 변경 가능.
- **예외·에러:** 닉네임 중복·형식 오류 → 필드 에러(Frame 01.2). 미입력 상태로 "시작하기" → 닉네임 포커스.
- **관련:** Frame 01.1 · 01.2 · `POST /api/users` · `User`, `UserInterest`, `GroupMember`

### F-03. 도서 검색 / 등록
- **목적 / 사용자 가치:** 표지·서지정보를 자동으로 채워 등록 부담을 없앤다.
- **진입 경로:** 일정 탭 "새 책 등록", 서재 탭 등록 버튼.
- **상세 동작:**
  1. 검색어 입력 → 알라딘·카카오 도서 API 호출 → 결과 리스트(표지·제목·저자·ISBN·쪽수).
  2. 책 선택 → 등록 확인 화면: 장르(6종 단일 선택), 읽기 시작일(기본 오늘).
  3. "등록하기" → `Book` 생성(status=reading), 서재·일정에 반영.
- **정책·규칙:** 제목 200자·저자 100자·ISBN 20자 이내(외부 API 값). 같은 사용자가 같은 ISBN 재등록 시 경고 후 기존 기록으로 이동 〔확정 필요〕. 검색 결과 0건 시 수동 입력 허용 여부 〔확정 필요〕. 시작일 미래 날짜 불가.
- **예외·에러:** API 키 미설정·호출 실패 → "검색을 불러오지 못했어요". 결과 0건 → Frame 08.
- **관련:** Frame 08 · 08.1 · 08.2 · (외부 검색 API) · `POST /api/books` · `Book`

### F-04. 서재 (내 책 목록)
- **목적 / 사용자 가치:** 내가 읽은/읽는 책을 한 곳에서 본다.
- **진입 경로:** 하단 탭 "서재".
- **상세 동작:**
  1. 필터 탭: 읽고 있는 책(reading) / 읽은 책(done).
  2. 제목 키워드 검색 + 정렬(최근순/제목순/완독일순).
  3. 책 카드: 표지·제목·저자·기간, 사진·소감 유무 아이콘. 탭 → 책 상세(F-05).
  4. 책 없음 → 빈 상태(Frame 07), 로딩 중 → 스켈레톤(Frame 07.1).
- **정책·규칙:** 본인 것만. 기본 정렬 최근 등록순.
- **예외·에러:** 로드 실패 → Frame 09 + 재시도.
- **관련:** Frame 03 · 07 · 07.1 · `GET /api/books` · `Book`

### F-05. 책 상세 / 독서 기록
- **목적 / 사용자 가치:** 그 책에 대한 감상·사진·기간을 남긴다.
- **진입 경로:** 서재·일정의 책 카드 탭.
- **상세 동작:**
  1. 헤더: 표지·제목·저자·읽은 기간(시작일~종료일 또는 진행 중, 일수 자동 계산).
  2. 장소 사진: 여러 장 업로드(S3 presigned URL), 장소 텍스트·좌표 선택 첨부, 가로 스크롤.
  3. 소감(`BookNote`): 여러 번 작성 가능한 노트. 상세엔 최신 1건, 탭하면 전체 이력.
  4. "다 읽었어요(완독 처리)": status=reading일 때만 노출 → status=done, 종료일 기록, "읽은 책"으로 이동.
  5. "이 책 공유하기": share_type=book 상태로 공유(F-07)로 이동.
- **정책·규칙:** 소감 1자 이상, 상한 〔확정 필요 — 현재 무제한(TEXT)〕. 사진 장수 상한 〔확정 필요〕. 위치 좌표는 사용자가 명시 첨부할 때만 저장(PRIVACY.md 1-2). 본인 기록만 편집·삭제.
- **예외·에러:** 사진 업로드 실패 → 개별 재시도. presigned URL 만료 → 재발급.
- **관련:** Frame 03.1 · `/api/books/{id}` · `/api/book-notes` · `/api/book-photos` · `Book`, `BookNote`, `BookPhoto`

### F-06. 독서 현황  · P1
- **목적 / 사용자 가치:** 앱을 열자마자 "지금 뭘 읽고 있고, 어디까지 읽었는지"를 보여준다.
  사용자 요구는 "내가 이 책을 언제부터 읽었더라"이며, 모임 일정 관리는 이 앱의 역할이 아니다.
- **진입 경로:** 하단 탭 첫 번째(앱 기본 진입 탭).
- **상세 동작:**
  1. 이번달 요약 — "이번달 · 지금까지 N권 완독" (`GET /api/dashboard`)
  2. 미니 캘린더 스트립 — 오늘 표시 + 책의 읽기 시작일/완독일 표시 (`Book.startDate`/`endDate`)
  3. 오늘의 리딩 카드 — 지금 읽는 책 + 진행률 + **"이어서 읽기"(탭 시 페이지 입력)**
  4. 미접속 배너 — N일 이상 미방문 시 (`/api/auth/me`의 `daysSinceLastLogin`)
  5. 알림 아이콘 — 안읽음 배지 (F-12)
  6. 새 책 등록 진입점
- **정책·규칙:**
  - **진행률: 기능은 필수, 입력은 선택.** `totalPages`가 있으면 `%` 표시, 없으면 "N일째 읽는 중" 폴백.
    총 페이지를 필수 입력으로 막지 않는다 — 도서 API가 항상 주지 않고, 막으면 등록 자체를 포기한다.
  - 페이지 갱신은 `PATCH /api/books/{id}/progress`. `currentPage >= totalPages`면 완독 처리 규칙 적용 검토.
  - **"이어서 읽기"에서 1탭으로 입력 가능해야 한다.** 서재 → 상세 → 입력은 3탭이라 실사용률이 떨어진다.
  - ⛔ **모임 일정 관리는 v1 범위에서 제외.** (OS 캘린더 연동 여부 논의도 함께 종결)
- **예외·에러:** 진행 중 책 없음 → 리딩 카드 대신 "새 책 등록" 유도.
- **관련:** Frame 02 (Frame 02.1 일정 상세는 **폐기**)

### F-07. 공유 (기록 / 대시보드)
- **목적 / 사용자 가치:** 완독·리캡을 원하는 범위로 자랑한다.
- **진입 경로:** 책 상세 "공유하기"(share_type=book) · 리캡 "공유 탭으로"(share_type=dashboard).
- **상세 동작:**
  1. 공유 대상 확인(책 또는 리캡).
  2. 공개 범위 선택: 전체 공개(all) / 그룹 선택(group) / 인원 직접 선택(custom).
  3. 공유 카드 미리보기(표지 + 소감 일부 + 기간 / 리캡 이미지).
  4. group·custom이면 "링크를 아는 누구나 볼 수 있어요" 안내를 확인받는다.
  5. 실행: 앱 내 공유(이력 기록) 또는 OS 공유시트로 SNS(instagram / threads / tiktok). 공개 링크(public_token)가 함께 생성된다.
- **정책·규칙:** platform은 app / instagram / threads / tiktok. scope와 무관하게 public_token은 링크 보유자면 접근 가능 → 사전 고지 필수. 카드 이미지는 클라이언트가 캡처해 S3 업로드(서버 렌더링은 범위 밖).
- **예외·에러:** 카드 생성 실패 → 재시도. custom 대상 0명 → 실행 비활성.
- **관련:** Frame 04 · `POST /api/share-records` · `ShareRecord`, `ShareRecordTarget`, `ShareRecordPhoto`

### F-12. 알림  · P1
- **목적 / 사용자 가치:** 그룹 참여, 월간 리캡 등 놓치면 아쉬운 것을 모아 본다.
- **진입 경로:** 독서 현황 탭 헤더 알림 아이콘 (안읽음 배지 포함).
- **상세 동작:** 알림 목록(종류·내용·시각·안읽음) · 탭 시 관련 화면으로 이동 · 읽음 처리.
- **정책·규칙:**
  - **v1은 인앱 알림만. 푸시는 v1.1.** (8.4 참고)
  - 알림 종류는 2종으로 확정: **그룹 참여 / 월간 리캡**.
  - 알림은 저절로 생기지 않는다 — 각 도메인 서비스에 발행 훅을 심어야 한다.
    **F-08 그룹이 동작해야 "그룹 참여"가 발생하므로 F-08이 선행이다.**
  - `Notification`에 이동 대상(`targetType`/`targetId`)을 반드시 포함한다. v1.1 푸시 payload에 재사용된다.
  - 프로필 설정에 알림 on/off 토글 자리를 미리 잡아둔다 (v1.1 수신 동의 UI 대비).
- **예외·에러:** 알림 없음 → "새 알림이 없어요".
- **관련:** Frame 10 · `GET /api/notifications` · `PATCH /api/notifications/{id}/read` · `GET /api/notifications/unread-count`

## 8. 공통 정책

### 8.1 회원 / 인증
- **가입**: 소셜 로그인 3종(카카오·구글·네이버)만. 이메일/비밀번호 가입 없음.
- **인증 유지**: 서버 발급 JWT, 만료 1시간. 리프레시 토큰 정책 〔확정 필요〕.
- **계정**: 소셜 `(provider, social_id)` 조합당 1개 회원. 제공자 간 계정 통합 미지원 〔확정 필요〕.
- **탈퇴**: 앱 내 "회원 탈퇴" → 확인 후 개인정보·독서 기록·사진·공유 기록 즉시 파기. 재가입 시 새 회원. (PRIVACY.md 5·6)
- **휴면**: 〔확정 필요 — 장기 미접속 계정 처리 여부·기간〕.
- **만 14세 미만**: 가입 대상이 아니다. 약관 동의 시 "만 14세 이상입니다" 확인으로 처리한다. 〔확정 필요 — 배포 전 결정〕

### 8.2 권한 / 등급
- **비회원(둘러보기)**: 공개 콘텐츠 조회만. 기록·공유·그룹 불가.
- **회원**: 본인 리소스 생성·수정·삭제. 타인 프로필·공개 기록은 조회만(공유 앱 특성상 조회 API는 열려 있음).
- **그룹 역할**: 소유자 / 멤버 2단계. 관리자 역할 필요 여부 〔확정 필요〕.

### 8.3 공개 범위

| 콘텐츠 | 선택 범위 | 기본값 |
|---|---|---|
| 독서 기록 공유(F-07) | 전체(all) / 그룹(group) / 인원지정(custom) | 〔확정 필요〕 |
| 리캡 공유(F-07) | 동일 | 〔확정 필요〕 |
| 프로필 | 전체 공개 / 비공개 〔확정 필요〕 | |
| 공유하지 않은 서재·독서 기록 | 본인만 | 본인만 |

- scope와 무관하게 공개 링크(public_token)는 링크 보유자면 접근 가능 → 공유 실행 전 고지 필수.
- 공개 웹페이지는 검색엔진 `noindex` 처리 〔확정 필요 — 권장〕.

- **v1은 인앱만.** 푸시(FCM/APNs)는 v1.1에서 다룬다. 푸시 도입 시 필요한 것:
  Firebase 프로젝트, `DeviceToken` 테이블 + 등록/해제 API, `POST_NOTIFICATIONS` 런타임 권한(Android 13+),
  포그라운드/백그라운드/종료 3상태 수신, APNs 인증키(Apple 개발자 계정 필요).
- **⚠️ 푸시 도입 시 법률 확인 필요.** "오늘 한 페이지 읽어볼까요?" 류 리마인더가 서비스 알림인지
  광고성 정보인지 경계에 있다. 광고성으로 분류되면 별도 수신 동의와 야간(21시~익일 08시) 발송 추가 동의가
  필요하다(정보통신망법). **발송 시간대 낮 고정 + 설정 on/off 토글**을 기본값으로 두고,
  판단이 애매하면 수신 동의 UI를 넣는 쪽으로 간다. (법률 자문 영역이며 이 문서가 단정하지 않는다.)
- 푸시 권한 요청 문구와 요청 시점은 v1.1 착수 시 정의한다.

**출시 플랫폼 — Android 선출시**

Mac이 없어 `pod install`·iOS 빌드·검증이 불가능하다. `react-native-encrypted-storage`,
Apple 로그인, 향후 Firebase가 전부 네이티브 모듈이라 Mac 없이는 iOS 빌드가 나오지 않는다.
- **v1은 Google Play(Android)로만 출시한다.**
- **Apple 로그인(`POST /api/auth/apple`) 코드는 v1에 구현해둔다** — 나중에 iOS를 낼 때 로그인부터
  다시 만들지 않기 위해서다. 다만 Service ID·Key 발급에 Apple 개발자 계정($99)이 필요하므로
  **실제 동작 검증은 iOS 착수 시점**이며, 그때까지 이 항목은 "코드 있음 / 미검증" 상태로 둔다.
- Apple 개발자 계정 결제도 iOS 착수 시점까지 보류한다.

**해소된 미결 사항**
〔그룹(F-08)을 빼면 공유의 group/custom 범위를 어떻게 처리할지〕
→ **F-08을 v1에 포함하므로 all/group/custom 전 범위를 지원한다.** 이 이슈는 종결.
