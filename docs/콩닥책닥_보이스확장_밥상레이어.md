# 콩닥책닥 보이스 확장 — "밥상" 레이어 v1

> 가이드라인은 유실됨, 이 문서와 ko.ts 주석이 현재 단일 출처
> 기본 규칙(어체·실패 문구·조사 처리)은 그대로 두고, **어디에 맛을 낼지**만 정합니다.

---

## 0. 왜 이 은유가 맞는가

기획서 5.1과 스토어 설명에 이미 답이 있습니다.

> 옛날에는 책 한 권을 다 떼면 **책거리**를 열어 **콩송편을 나눠 먹으며** 축하했습니다.

책거리는 "혼자 다 읽었다"가 아니라 **"다 읽었으니 같이 먹자"** 는 풍속입니다.
그래서 음식 은유가 앱의 세 축에 그대로 대응됩니다.

| 앱의 핵심 가치 | 책거리에서의 대응 | 쓸 수 있는 말 |
|---|---|---|
| 기록한다 | 한 술씩 뜬다 | 한 입, 두 모금, 야금야금, 첫 술 |
| 자랑한다 | 나눠 먹는다 | 책거리, 나눠 먹기, 한 상 차리기 |
| 돌아본다 | 뭘 먹었나 본다 | 밥상, 입맛, 올해의 상 |

이건 "귀여우니까 음식 말을 쓰자"가 아니라, **원래 이 앱이 하려던 말**입니다.
그래서 은유를 쓸 때는 항상 이 대응 안에서 씁니다. 대응 밖의 음식 말(맛있다, 배부르다, 요리하다)은 브랜드와 상관없는 장식이라 쓰지 않습니다.

## 1. 선 세 개

### 선 1 — 빈도가 높을수록 담백하게

같은 문구를 세 번째 보면 귀여움은 짜증이 됩니다.

| 빈도 | 예시 | 맛 |
|---|---|---|
| 매일·매번 | 소감 저장, 책 등록, 사진 추가 | **없음** — `소감을 저장했어요` |
| 가끔 | 완독, 공유, 월간 리캡 | **진하게** — `책거리! 완독으로 기록했어요` |
| 평생 한 번 | 첫 책 등록, 첫 완독, 100권 | **가장 진하게** — 이 순간을 위해 아껴둡니다 |

> 완독 토스트에 맛을 넣는 건 괜찮습니다. 연 2~3권 읽는 페르소나 A에게는 1년에 세 번 보는 문구니까요. 하지만 소감 저장은 한 권에도 여러 번 일어납니다.

### 선 2 — 잘 됐을 때만 맛을 낸다

**실패·경고·삭제·권한·약관에는 음식 말을 쓰지 않습니다.**

```
❌ 책을 못 삼켰어요
❌ 서재 상이 엎어졌어요
❌ 이 기록, 상에서 내릴까요?

✅ 책을 검색하지 못했어요. 잠시 후 다시 시도해주세요
✅ 삭제한 소감은 되돌릴 수 없어요
```

실패한 순간의 장난스러운 말투는 사용자에게 **조롱으로 읽힙니다.**
사진 업로드가 세 번 실패한 사람에게 "앗, 체했나 봐요"는 앱을 지우게 만드는 문장입니다.

| 표면 | 맛 |
|---|---|
| 빈 상태, 완독, 리캡 하이라이트, 공유 카드, 온보딩, 복귀 배너, 알림 | ✅ |
| CTA·탭·필드 라벨 | ⚠️ §2 참고 |
| 에러, 네트워크, 권한, 삭제 확인, 로그아웃, 약관·개인정보 | ❌ 절대 |

### 선 3 — 읽은 양을 음식으로 평가하지 않는다

이게 가장 위험한 지점입니다. 음식 은유는 "많이/적게 먹었다"로 미끄러지기 쉽고, 그 순간 **먹는 양을 평가하는 문장**이 됩니다.

```
❌ 이번 달엔 조금밖에 못 드셨네요
❌ 완전 편식이에요!
❌ 이번 주는 굶으셨군요
❌ 독서 다이어트 중인가요?
```

기획서 KPI가 "기록이 부담스럽지 않다고 느낀다 70%"이고, 페르소나 A는 **연 2~3권 라이트 리더**입니다. 이 사람에게 적게 먹었다고 말하는 순간 앱의 전제가 무너집니다.

**절대 금지어**: 굶다 · 다이어트 · 폭식 · 과식 · 편식 · 배부르다 · 그만 먹다 · 소화 못 하다 · 체하다 · 맛없다 · 상하다

> 특히 `굶다`·`다이어트`·`폭식`은 섭식 관련 표현이라 재미로도 쓰지 않습니다.
> `배부르다`는 "이제 그만 읽어도 된다"는 뜻이 되어 앱 목적과 반대입니다.

## 2. 은유는 설명에만, 기능 이름은 직역으로

**사용자가 기능을 못 찾으면 은유는 실패입니다.**

| 자리 | 규칙 | 예 |
|---|---|---|
| 탭 이름 | 직역 고정 | `서재` (❌ 밥상) |
| 버튼 라벨 | 직역 고정 | `서재에 책 등록하기` (❌ 상에 올리기) |
| 필드 label | 직역 고정 | `장르` (❌ 입맛) |
| 화면 제목 | 직역 고정 | `독서 대시보드` |
| **빈 상태 설명** | 맛 OK | `한 권만 다 읽어도 입맛이 보이기 시작해요` |
| **토스트·배너** | 맛 OK | `책거리! 완독으로 기록했어요` |
| **리캡 하이라이트** | 맛 진하게 | `이번 분기 입맛은 '인문'이었네요` |
| **공유 카드** | 맛 진하게 | 앱 밖으로 나가는 자랑용 표면 |
| **스토어·스플래시** | 맛 진하게 | 이미 그렇게 쓰고 있음 |

> 예외: `입맛`은 리캡 하이라이트 **문장 안에서만** 씁니다. 프로필 편집의 `관심 분야` label은 그대로 둡니다.

## 3. 어휘 사전

### 써도 되는 말

| 말 | 뜻 | 쓰는 자리 |
|---|---|---|
| **책거리** | 완독 축하 | 완독 토스트, 공유 카드 — **브랜드 고유어, 가장 아껴 쓸 것** |
| **콩송편** | 완독 보상 | 첫 완독, 마일스톤 |
| 한 입 | 짧은 독서 단위 (5~10p) | 복귀 배너, 이어읽기 |
| 두 모금 | 아주 짧은 분량 | 진행률 90% 이상일 때 |
| 야금야금 | 꾸준히 조금씩 | 태그라인, 연속 기록 |
| 첫 술 | 첫 기록 | 온보딩 |
| 한 상 / 밥상 | 모아둔 결과 | 서재 빈 상태, 리캡 |
| 입맛 | 장르 취향 | 리캡 하이라이트만 |
| 뜸 들이다 | 오래 붙잡고 읽는 중 | 리캡 "가장 오래 읽은 책" |
| 뚝딱 | 빨리 읽음 | 리캡 "가장 빨리 읽은 책" |
| 나눠 먹다 | 공유 | 공유 성공 토스트 |
| 골고루 | 다양한 장르 | 리캡 (❌ 반대말로 "편식" 쓰지 말 것) |
| 군침 | 읽고 싶음 | 읽을 예정 상태 설명 |

### 톤 조절

- 한 화면에 은유는 **하나만**. 두 개 겹치면 코스프레가 됩니다.
- 이모지는 **음식 은유가 있는 자리에만**, 한 문장에 하나. `🫘`(완독) `🍚`(리캡) 정도.
- `~네요` 를 조심스럽게 씁니다. 리캡 하이라이트처럼 앱이 관찰한 걸 말할 때만 자연스럽습니다.

## 4. 실제 문구 — 담백안 vs 맛있는 안

> 아래는 그 위에 맛을 얹은 버전입니다.
> **둘 중 하나를 고르는 게 아니라, §1 빈도·표면 규칙에 따라 자리별로 나눠 씁니다.**

### 온보딩 · 첫 경험 (맛 진하게)

| 자리 | 현재 | 담백안 | 맛있는 안 |
|---|---|---|---|
| 로그인 태그라인 | `오늘 읽은 한 페이지를 자랑해보세요` | 유지 | 유지 — 스토어 캡션으로 확정된 문구라 건드리지 않습니다 |
| 로그인 보조 | — | — | `한 입씩 야금야금, 그래도 쌓여요` |
| 가입 안내 | `몇 가지만 알려주세요` | 유지 | 유지 |
| 가입 완료 다이얼로그 | `가입을 환영해요!` / `지금 바로 서재에 책을 꽂아보시겠어요?` / `건너뛰기` / `네` | `가입을 환영해요!` / `첫 책을 서재에 꽂아볼까요?` / `나중에 할게요` / `책 등록하러 가기` | `어서 오세요!` / `첫 술은 가볍게 — 책 한 권만 올려볼까요?` / `나중에 할게요` / **`책 고르러 가기`** |
| 첫 책 등록 성공 (1회 한정) | `서재에 등록했어요` | 유지 | **`첫 책이 상에 올랐어요!`** |

### 서재 (담백 위주)

| 자리 | 현재 | 담백안 | 맛있는 안 |
|---|---|---|---|
| 최초 빈 서재 | (빈 상태 CTA) | `아직 등록한 책이 없어요` / `첫 책 한 권이면 서재가 시작돼요` | `아직 상이 비어 있어요` / `한 권만 올려도 서재가 시작돼요` / `[서재에 책 등록하기]` |
| 검색 결과 없음 | `해당하는 책이 없어요` | `찾는 책이 없어요` / `검색어나 필터를 바꿔보세요` | **담백안 유지** — 실패 상태 (§1 선 2) |
| 등록 성공 | `서재에 등록했어요` | 유지 | **담백안 유지** — 고빈도 (§1 선 1) |
| 읽을 예정 빈 상태 | — | `읽을 예정인 책이 없어요` | `아직 안 뜯은 책이 없네요` / `군침 도는 책을 미리 담아두세요` |

### 책 상세 · 완독 (맛 진하게)

| 자리 | 현재 | 담백안 | 맛있는 안 |
|---|---|---|---|
| 완독 버튼 | `다 읽었어요 (완독 처리)` | `다 읽었어요` | **담백안 유지** — 버튼 라벨은 직역 (§2) |
| 완독 토스트 | `완독 처리했어요` | `완독으로 기록했어요` | **`책거리! 완독으로 기록했어요`** |
| 완독 진행 중 | `처리하는 중…` | `기록하는 중…` | 담백안 유지 |
| 소감 없음 | `아직 작성한 소감이 없어요` | 유지 | `아직 소감이 없어요` / `한 줄이라도 남겨두면 나중에 반가워요` |
| 소감 placeholder | `이 책을 읽으며 든 생각을 자유롭게 남겨보세요` | 유지 | 유지 — 이미 좋습니다 |
| 소감 저장 | `소감을 저장했어요` | 유지 | **담백안 유지** — 고빈도 |

### 일정 · 복귀 (맛 살짝)

| 자리 | 현재 | 담백안 | 맛있는 안 |
|---|---|---|---|
| 이어읽기 배너 | `오늘은 『{책}』를 마저 읽을 차례예요!` | 조사 유틸 적용 | `오늘은 『{책}』{josa} 마저 읽을 차례예요` |
| 이어읽기 보조 (진행률 90%↑) | `어제 {n}p까지 읽었어요 · 진행률 {n}%` | 유지 | **`두 모금이면 끝나요 · {n}%`** ← 조건부 문구 |
| 복귀 배너 | `{n}일 동안 방문하지 않으셨어요. 오늘 한 페이지 읽어볼까요?` | `{n}일 만이에요. 오늘 한 페이지만 읽어볼까요?` | **`{n}일 만이네요. 오늘은 한 입만 어때요?`** |

> 복귀 배너는 §1 선 3에 가장 가까이 가는 문구입니다. `{n}일 만이네요` 까지만 사실을 말하고, 안 온 이유나 양은 언급하지 않습니다.

### 리캡 (맛 가장 진하게)

| 자리 | 현재 | 담백안 | 맛있는 안 |
|---|---|---|---|
| 최다 장르 | `이 기간 가장 많이 읽은 장르는 '{장르}'예요` | 조사 유틸 적용 | **`이번 {기간} 입맛은 '{장르}'{josa}`** |
| 가장 오래 읽은 책 | `가장 오래 읽은 책은 «{책}»({n}일)이에요` | 기호를 『』로 | **`『{책}』{josa} {n}일 동안 뜸 들여 읽으셨어요`** |
| 가장 빨리 읽은 책 | `가장 빠르게 읽은 책은 «{책}»({n}일)이에요` | 기호를 『』로 | **`『{책}』{josa} {n}일 만에 뚝딱`** |
| 단일 장르만 읽음 | — | — | `이번 {기간}엔 '{장르}'에 푹 빠지셨네요` ← ❌ "편식" 쓰지 않음 |
| 대시보드 빈 상태 | `아직 완독한 책이 없어요` | + `첫 책을 다 읽으면 장르 취향을 보여드릴게요` | **`아직 상이 비어 있어요`** / `한 권만 다 읽어도 입맛이 보이기 시작해요` |

### 공유 (카드는 진하게, 버튼은 담백)

| 자리 | 현재 | 담백안 | 맛있는 안 |
|---|---|---|---|
| 공유 버튼 | `앱 내 공유` / `SNS 공유` | `콩닥책닥에서 공유` / `SNS 공유` | **담백안 유지** — 버튼 라벨 (§2) |
| 공유 성공 토스트 | — | `공유했어요` | **`잘 나눴어요!`** |
| 공유 카드 하단 워터마크 | — | `콩닥책닥` | **`책거리 중 · 콩닥책닥`** |
| 공개 범위 경고 | `이 링크를 아는 사람은 누구나 볼 수 있어요` | 유지 | **담백안 유지** — 경고 (§1 선 2) |
| 공유 빈 상태 | `서재에서 공유할 책을 먼저 선택해주세요` | 제목/설명/CTA 3요소로 | `나눠 먹을 책을 골라주세요` / `서재에서 책을 고르면 공유 카드를 만들 수 있어요` / `[서재로 가기]` |

### 알림

| 자리 | 현재 | 맛있는 안 |
|---|---|---|
| 월간 리캡 | `월간 리캡이 도착했어요` / `7월 독서 대시보드를 확인해보세요` | **`7월 밥상이 차려졌어요`** / `이번 달 뭘 읽으셨는지 볼까요?` |
| 공유 반응 | `공유한 기록에 반응이 있어요` / `『아몬드』 공유 카드에 좋아요가 달렸어요` | 유지 |
| 그룹 초대 | `새 멤버가 참여했어요` | 유지 |

## 5. 마일스톤 — 맛을 아껴뒀다가 쓰는 자리

기획서 KPI(7일 내 첫 기록 40%, 4주 잔존 20%)에 직접 붙는 순간들입니다.
평소에 담백하게 쓴 덕분에 이 문구들이 특별해집니다.

| 시점 | 문구 |
|---|---|
| 첫 책 등록 | `첫 책이 상에 올랐어요!` |
| 첫 완독 | `첫 책거리네요 🫘 콩송편 나눠 먹을 차례예요` |
| 첫 공유 | `처음으로 나눠 드셨어요!` |
| 10권 완독 | `열 권째 책거리예요` |
| 연간 리캡 | `올해 차린 상, 한번 볼까요?` |

> 마일스톤 문구는 **한 사용자에게 평생 한 번**만 보입니다. 여기에는 이모지와 은유를 마음껏 써도 됩니다.

## 6. 구현 메모

- 조건부 문구(진행률 90% 이상 `두 모금`, 첫 등록 `첫 책이 상에`)가 생기므로, 가이드라인 부록의 `constants/messages.ts` 분리가 사실상 필요해집니다. 화면 안에서 `if (isFirst)` 로 문자열을 분기하면 금방 흩어집니다.
- 은유가 들어간 문구는 조사 문제가 더 자주 생깁니다(`『{책}』{josa} 뚝딱`). 조사 유틸(§가이드라인 6)을 먼저 넣는 순서를 지켜주세요.
- 다국어 계획이 있다면 `야금야금`·`두 모금`·`뜸 들이다`는 번역 불가입니다. 키를 분리하고 언어별로 다른 은유를 쓰거나, 해당 언어에서는 담백안으로 폴백하는 구조가 필요합니다.
- 마일스톤 문구는 서버가 "몇 번째인지"를 알려줘야 합니다. 완독 응답에 `completedCount` 같은 필드가 없다면 백엔드 요청 항목입니다.

## 7. 체크리스트 (가이드라인 §13에 추가)

- [ ] 이 문구가 나오는 빈도는? 매번 나온다면 맛을 뺐는가
- [ ] 실패·경고·삭제·권한 자리에 은유를 쓰지 않았는가
- [ ] 읽은 양을 평가하는 뉘앙스가 없는가 (선 3)
- [ ] 금지어를 쓰지 않았는가 (굶다·다이어트·폭식·편식·배부르다·소화·체하다)
- [ ] 탭·버튼·필드 label을 은유로 바꾸지 않았는가
- [ ] 한 화면에 은유가 두 개 이상 겹치지 않는가
- [ ] `책거리`·`콩송편`을 남발하지 않았는가 (완독·마일스톤 전용)
